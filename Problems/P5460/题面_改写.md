# 工单编排与检索基础测验

**1、园区夜间巡检系统用并查集维护连通的巡检点。当前 parent 关系为 $6\to 3$、$3\to 9$、$9\to 1$、$1\to 1$。对 $6$ 执行带路径压缩的 find 后，parent 关系会怎样变化?**
{{ select(1) }}
- 只把 $6$ 接到 $9$，其余节点保持原链
- 把根节点 $1$ 拆成两个集合并交换编号
- $6$、$3$、$9$ 都更直接指向根节点 $1$ 附近
- 把尚未访问的巡检点并入当前集合

**2、夜间规章审阅集群要并行处理多路长文档问答。KV Cache 随会话数和文档 token 数迅速占满显存。在不修改模型权重且要兼顾吞吐与时延时，应优先怎么做?**
{{ select(2) }}
- 把显存换成主机内存后关闭分页，让每条请求独占整卡
- 结合上下文上限、并发数以及分页和淘汰策略控制占用
- 把所有会话的 KV 压成一份共享向量，解码时再按会话还原
- 每个解码步都把历史 KV 写到磁盘再读回，以换取更大并发

**3、质检台账助手做监督微调。同一条「填写缺陷描述」指令下，训练集里出现多份互相矛盾的标准回复。最直接的风险是?**
{{ select(3) }}
- 只要把学习率调大，冲突标签会被多数类覆盖
- 验证集会把矛盾回答平均成一条新标签
- 矛盾样本会自动变成偏好对，SFT 阶段就能完成对齐
- 监督信号冲突，使模型响应风格和事实边界不稳定

**4、实验室预约台的 Agent 需要调用两个工具：先查仪器是否仍被占用，再决定是否释放预约。更合理的链路是?**
{{ select(4) }}
- 占用查询超时就按预约人加急申请直接放行
- 把两个工具合成一次无返回值的调用，由模型口头确认占用
- 模型产出结构化计划，系统校验占用状态后释放预约
- 先释放预约，再用占用查询结果事后补写日志

**5、变电站检修助手从规程库召回了正确手册，但关键段落排名靠后，没有进入注入上下文。更应优先优化什么?**
{{ select(5) }}
- 把生成温度提高到 $1.5$ 让模型自行补全未注入段落
- 重排和上下文截取规则
- 把检索库改成只存标题，正文全部丢掉
- 关闭引用约束，允许模型不依据检索片段作答
