# 所有模块的构建顺序

## 题目描述

某公司正在开发一个大型软件系统，系统包含 $N$ 个模块，每个模块之间存在构建依赖关系。例如，模块 $A$ 可能依赖于模块 $B$，这意味着必须先构建模块 $B$，才能构建模块 $A$。

请根据依赖关系，输出所有可能的模块构建顺序（按照构建顺序排列模块名称），要求：

1. 每个合法的构建顺序作为一个结果（一条字符串中，模块名从左到右为构建先后，**相邻模块名之间为一个空格**）。
2. 多个结果按**整条字符串**的字典序升序排序后输出。
3. 如果存在循环依赖（依赖成环），则没有合法的构建顺序，返回**空数组** `[]`。

评测采用 **LeetCode 核心代码模式**：只需实现 `Solution` 类中的方法，平台负责读入并调用。**不要**编写 `main` 或自行处理标准输入输出（本地 `template.*` 仅用于对齐造数与自测）。

## 依赖含义

- 输入中的每个依赖对为 **`[依赖模块, 被依赖模块]`**：前者依赖后者，因此被依赖模块必须在依赖模块**之前**构建。
- 示例：`["user","auth"]` 表示 `user` 依赖 `auth`，合法顺序中 `auth` 出现在 `user` 左侧。

## 方法签名

三种语言类名均为 `Solution`，请实现：

- **C++**：`vector<string> allBuildOrders(vector<string>& modules, vector<vector<string>>& dependencies);`
- **Java**：`public List<String> allBuildOrders(List<String> modules, List<List<String>> dependencies)`
- **Python**：`def allBuildOrders(self, modules: List[str], dependencies: List[List[str]]) -> List[str]:`

### 参数说明

- `modules`：长度为 $N$ 的模块名列表，名称互不相同，仅由数字与大小写字母组成，$N \le 100$。
- `dependencies`：依赖关系列表，长度 $< 100$；每个元素为长度 $2$ 的列表 `[x, y]`，表示 **$x$ 依赖 $y$**（$y$ 必须先于 $x$ 构建）。可为空列表；保证 `x,y` 均在 `modules` 中且不出现重复依赖对。

### 返回值

- 若无环：返回所有合法拓扑排序对应的字符串列表；每个字符串为一次完整构建顺序，模块名之间**一个空格**分隔；列表整体按字符串字典序升序排序。
- 若有环：返回空列表 `[]`（Python `[]`，Java/C++ 空 `List` / 空 `vector`）。

**备注**：题目保证合法构建顺序的条数 $< 10!$（$10! = 3628800$），因此可以在保证复杂度的前提下枚举所有拓扑序；若仅做环检测可用 `O(N+M)`。

## 输入格式（平台侧，选手无需编写）

**单行**文本，与官方样例同形：先给出模块名的一维数组字面量，**英文逗号**后给出依赖的二维数组字面量；整体可被 Python `(" + 行 + ")"` 形式的元组字面量解析为 `(modules, dependencies)`（即两结构外层为**圆括号**包起来的**逗号分隔二元组**，或等价地直接解析为两个相邻的 `list` 字面量）。

形态示例（无多余空格亦可，解析器以样例为准）：

```text
["user","auth","database","api"],[["user","auth"],["auth","database"],["api","database"]]
```

- 模块名、依赖中的名称均为双引号包裹的 JSON 风格字符串。
- 依赖对内两个字符串顺序固定为 `[依赖模块, 被依赖模块]`。

## 输出格式

**一行**：合法顺序列表的 **JSON** 表示：

- 字符串元素用双引号包裹，内部模块名以空格分隔；
- **数组内逗号后无空格**（与 `json.dumps(..., separators=(',', ':'))` 一致）；
- 行末**恰好一个**换行符 `\n`。

无合法顺序时输出：

```text
[]
```

## 样例 1

**输入**

```text
["user","auth","database","api"],[["user","auth"],["auth","database"],["api","database"]]
```

**输出**

```text
["database api auth user","database auth api user","database auth user api"]
```

**说明**

- 依赖：`user` 依赖 `auth`，`auth` 依赖 `database`，`api` 依赖 `database`，故 `database` 必须第一个构建。
- 合法拓扑排序共 $3$ 种；按结果字符串字典序排序后如上。

## 样例 2

**输入**

```text
["A","B","C"],[["A","B"],["B","C"],["C","A"]]
```

**输出**

```text
[]
```

**说明**

存在环 $A \to B \to C \to A$，无合法构建顺序。
