# 答案与解析

**1、答案：B**

LRU 需要按访问先后移动节点，哈希表定位后必须 $O(1)$ 删除/插入。双向链表能在已知节点上 $O(1)$ 摘下并接到表头；优先队列、平衡树做不到均摊 $O(1)$，跳表也不按访问顺序维护。

**2、答案：C**

KV Cache 保存各层已算好的 Key/Value，自回归时不必对旧 token 重算注意力键值。它不改注意力公式，短文本也能用，缓存的也不是原文或梯度。

**3、答案：A**

先序根左右、中序左根右。先序首元素「仓」为根；中序里「仓」左侧仅「棚」，故左子树是叶「棚」。右侧中序为坞闸港、先序为闸坞港，故右子树根为「闸」，左「坞」、右「港」。后序左右根：棚、坞、港、闸、仓。

**4、答案：B**

MoE 由门控网络给每个 token 打专家分，只激活 Top-k 个专家。不是按显存轮询、不是整句绑死一个专家、也不是随机丢掉一半再平均。

**5、答案：C**

因果注意力下，位置 `28` 一改，该位置及之后所有 Query 都会看到新的前缀，对应 KV 全部作废，必须从修改处重算。只动输出层、保住第 `28` 位缓存、或只改位置编码，都会用到过期的 K/V。

**6、答案：C**

即使加锁与解锁写在同一线程里，非可重入锁被同一线程重复获取且未释放，仍可能死锁。C 把「同一线程」当成充分条件，是错的。进程/线程职责、共享地址空间与独立栈、创建进程更重，都说得通。

**7、答案：C**

向量检索只做粗召回，相似度与真实相关性有差距。Reranker 用 query 与片段做细粒度打分，提升 Top-K。它不替代向量库，也不靠加长分片或加噪声。

**8、答案：B**

错误码适合倒排词法精确命中，处理说明适合向量语义召回。两路结果去重后再重排，才能两边都照顾到。只走过滤器、丢掉错误码、或只比标题编辑距离，都会漏一路信号。

**9、答案：A**

推测解码里，目标模型一旦拒绝当前草稿 token，该位置之后的小模型候选全部作废，按大模型分布重采样当前位置，再继续。不能把拒绝当接受，也不能改抽小模型或整段改贪心。

**10、答案：B**

自然语言约定 JSON 不稳定。Function calling 在协议层约束参数结构，工程上最稳。肉眼检查、数换行、只靠温度，都不是可靠约束。

**11、答案：C**

`READ COMMITTED` 通常按语句执行时已提交的版本读，没有贯穿整个事务的固定快照，所以乙提交后甲第二次查询能见到新值（不可重复读）。不会自动升到可串行化，也不是「已提交永远不可见」。

**12、答案：C**

这是冗长偏差：长度被当成质量代理。晕轮、逆反、框架说的是别的认知偏差。

**13、答案：A**

缺页且磁盘内容有效时：选空闲或置换页框，把目标页装入，更新页表后再重试原指令。结束进程、只冲指令缓存、当非法访问杀掉线程，都不是缺页处理。

**14、答案：A**

训练目标是预测下一个 token 的概率，不是核对事实，这是幻觉的根。温度、标点、梯度裁剪都不是根本原因。

**15、答案：A**

fork 默认写时复制：先只读共享物理页，子作业写入某页时才复制该页。不必一上来拷整份地址空间，更不能共用可写页互相覆盖，也不必先全部换出。

**16、答案：B**

HTTP 在应用层，SSH 同层。LLDP 偏链路发现，OSPF 是路由（网络层），NDP 是邻接发现，都不是应用层。

**17、答案：A**

生成侧 BPE 一换，同一段文本的 token 数和切分都变，提示、分隔符、候选片段都要按新词表重算占用。检索向量库不必为生成分词器重建；旧下标和关掉窗口限制都会切错。

**18、答案：A**

窗口有限，要塞进真正相关且信息密度够的内容，否则注意力被稀释。不是越长越好，也不是按空格截断或把系统提示放到窗外。
