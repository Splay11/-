# 模型工程与系统基础选择

**1、边缘网关要按访问顺序淘汰最久未使用的会话键，并且 `get` 和 `put` 的平均时间复杂度都为常数级。在哈希表之外，最合适的辅助结构是?**
{{ select(1) }}
- 按访问次数维护的优先队列
- 记录访问顺序的双向链表
- 按键值维护的平衡搜索树
- 按过期时间维护的跳表

**2、客服模型用自回归方式续写工单。关于推理优化中的 KV Cache，以下哪种理解是正确的（）**
{{ select(2) }}
- 只缓存最后一层的注意力分数
- 把整段 prompt 的梯度存进显存以加速反传
- KV Cache缓存已计算层Key/Value张量，避免自回归生成重复计算
- 用磁盘页缓存用户原文以加速 tokenize

**3、已知二叉树的先序遍历序列为仓棚闸坞港，中序遍历序列为棚仓坞闸港，则后序遍历序列为（ ）**
{{ select(3) }}
- 棚坞港闸仓
- 仓闸棚坞港
- 棚闸仓港坞
- 坞港仓棚闸

**4、多专家质检网络把每个片段交给不同专家子网。MoE架构中，路由机制的工作方式是（）**
{{ select(4) }}
- 按显存空闲量轮询唤醒专家
- 门控网络为每个token输出各专家的权重分数，选取Top-k个专家进行计算
- 用同一专家处理整条序列所有位置
- 随机丢弃一半专家后再对剩余结果取平均

**5、对话式大模型采用因果注意力和 KV Cache。第 `28` 个位置的输入被修改，而第 `29` 个位置及其后的原始 token 均未改变。为保证后续生成使用正确上下文，通常应如何处理?**
{{ select(5) }}
- 只作废输出层权重，中间层 KV 继续复用
- 从序列开头完整重算，但不能动第 `28` 位的缓存
- 使第 `28` 个位置及其后的相关 KV 缓存失效，并从修改位置重新计算
- 仅刷新第 `29` 位以后的位置编码，K/V 保持不变

**6、下列关于进程管理说法错误的是（）**
{{ select(6) }}
- 进程是资源分配的基本单位，线程是调度的基本单位
- 同一进程内的线程共享地址空间，但各自拥有独立栈
- 采用锁来访问线程共享资源时，如果加锁和解锁操作处在同一个线程中，则不会导致死锁
- 创建进程的开销通常大于创建线程

**7、规章检索台先用向量库召回片段，再引入 Reranker（重排序模型）。其主要工程价值是（）**
{{ select(7) }}
- 用倒排索引完全替换向量库
- 把分片长度加倍以减少召回次数
- 弥补向量检索细粒度排序不足，提升Top-K相关性
- 在生成阶段插入随机噪声提高多样性

**8、运维助手要回答 “错误码 F2209 如何处理”，知识库同时提供倒排索引和向量索引。为了兼顾错误码的精确匹配和处理流程的语义召回，较合适的做法是?**
{{ select(8) }}
- 把查询整段哈希后只走布隆过滤器
- 保留错误码做词法召回，并结合语义召回结果去重后重排
- 丢掉错误码，只按文档更新时间排序
- 仅用最短编辑距离在标题里扫一遍

**9、草稿小模型先写出候选 token，目标大模型逐个验证（推测解码）。若某一步大模型拒绝了候选 token，正确的处理原则是?**
{{ select(9) }}
- 丢弃被拒绝位置之后的小模型候选，并按校正后的大模型分布采样替代 token
- 把拒绝当作接受，以换取更高吞吐
- 从小模型词表里再随机抽一个 token 顶上
- 回退到整段贪心解码并丢弃大模型结果

**10、工单系统要把模型输出收成固定字段。在LLM应用中实现可靠的结构化输出，工程实践中最稳健的方案是（）**
{{ select(10) }}
- 只在温度为 `0` 时口头约定 JSON 形状
- 通过function calling在协议层强制约束输出结构
- 生成后再靠人工肉眼检查格式
- 用换行数量判断是否已经结构化

**11、事务甲在 `READ COMMITTED` 隔离级别下两次执行同一条普通查询。两次查询之间，事务乙更新了其中一行并提交了事务。甲第二次查询读到新值，最能解释这一现象的是?**
{{ select(11) }}
- 隔离级别会在第二次查询时自动升到可串行化
- 普通查询一直沿用事务启动瞬间的快照
- 每条语句通常基于执行时已提交的可见版本判断
- 已提交的更新对未结束事务始终不可见

**12、偏好标注台上，标注员常常选更长的客服回复而忽视内容质量。该现象称为（）**
{{ select(12) }}
- 晕轮效应，因排版美观就给更高分
- 逆反效应，刻意挑选更短的回复
- 冗长偏差，回复长度成为质量的代理信号干扰判断
- 框架效应，选项措辞一变偏好就翻转

**13、系统使用分页存储管理。某进程访问一个页面，该页面已经建立虚拟地址映射，但当前不在物理内存中，且对应的磁盘内容有效。处理缺页异常时，最关键的顺序是?**
{{ select(13) }}
- 选择空闲页框或置换页框，装入目标页并更新页表后重试原指令
- 先结束进程再重新建立映射
- 只刷新指令缓存，不把页面装入内存
- 把缺页当作非法访问，直接结束该线程

**14、值班问答模型有时会写出看似完整却与事实不符的段落。大模型产生“幻觉”的根本原因是（）**
{{ select(14) }}
- 模型基于概率预测生成文本，其目标并非事实验证
- 解码温度过低导致只会复读训练语料
- 词表里缺少标点，所以必须编造事实
- 梯度裁剪把事实记忆全部冲掉

**15、父作业拉起子作业后，二者暂时共享同一批物理内存页。随后子作业只修改其中一个页面，操作系统通常会如何处理?**
{{ select(15) }}
- 触发写时复制，只为被修改的页面建立副本
- 立即复制全部地址空间，再允许子作业运行
- 父子共用同一可写页，并互相覆盖修改
- 先把全部页换出到磁盘，再分别为两者换入

**16、在 TCP/IP 分层标准中与 HTTP 协议工作在同一层的协议有（）**
{{ select(16) }}
- 链路发现用的 LLDP
- SSH
- 路由通告用的 OSPF
- 邻居发现用的 NDP

**17、团队只更换了生成模型的 BPE 分词器，检索器、向量索引和候选文档排序均不变；上下文窗口仍按新分词器的 token 数限制。哪个处理最必要?**
{{ select(17) }}
- 用新分词器重新计算候选片段、提示模板和分隔符的 token 占用
- 按旧分词器记下的 token 下标去切新输入
- 把向量库维度改成新词表大小
- 关闭上下文窗口限制，不再统计占用

**18、上下文工程中，“上下文窗口管理”的核心挑战是（）**
{{ select(18) }}
- 在有限窗口内平衡信息密度与相关性，避免注意力稀释
- 窗口必须等于训练时的最大长度，否则无法推理
- 只统计空格数来决定截断点
- 把系统提示放到窗口之外单独计算
