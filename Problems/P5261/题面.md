# 题目内容

游戏活动上线前，运营平台会为每个活动场景准备一组资源包，并分别在 $android、ios、pc$ 三个平台生成资源就绪记录。为了提前发现资源包发布缺口，需要根据资源计划和平台检查日志，输出仍缺少就绪记录的资源包清单。

请使用 $Bash$ 编写脚本，生成活动资源包缺失清单。



# 输入描述


第一行包含两个整数 $R,C(1 \le R \le 10000,0 \le C \le 30000)$。$R$ 表示资源计划记录数量，$C$ 表示平台检查日志数量。

随后 $R$ 行，每行包含 $3$ 个空白分隔字段：$resource\_id$ $scene$ $required\_version$。字段含义：$resource\_id$ 表示资源包 $ID$；$scene$ 表示活动场景；$required\_version$ 表示本次活动要求发布的资源版本。

再随后 $C$ 行，每行包含 $4$ 个空白分隔字段：$resource\_id$ $version$ $platform$ $status$。

$platform$ 只会是 $android、ios、pc$；$status$ 只会是 $READY$ 或 $FAIL$。

统计规则：对每条资源计划，只有在 $required\_version$ 下同时存在 $android、ios、pc$ 三个平台的 $READY$ 记录，才认为该资源包发布完整。同一资源包、同一版本、同一平台可以出现多条记录，只要存在至少一条 $READY$ 即可；$FAIL$ 不能替代 $READY$；非 $required\_version$ 的记录不计入；未出现在资源计划中的日志忽略。

各字段长度为 $1$ 到 $50$，只包含大小写字母、数字、点号、下划线和短横线；$resource\_id$ 在资源计划中互不重复。输入保证格式合法，无空行，无多余空格。


# 输出描述


按资源计划中给出的先后顺序，逐行输出每个发布不完整的资源包的 $resource\_id$。若所有资源包均发布完整，输出 $none$。


## 样例1 



**输入** 



```
3 7
pkg_a scene1 v1.0
pkg_b scene1 v1.0
pkg_c scene2 v2.0
pkg_a v1.0 android READY
pkg_a v1.0 ios READY
pkg_a v1.0 pc READY
pkg_b v1.0 android READY
pkg_b v1.0 ios FAIL
pkg_b v1.0 pc READY
pkg_c v1.5 android READY
```



**输出** 



```
pkg_b
pkg_c
```



**说明**

$pkg\_a$ 在要求版本 $v1.0$ 下三个平台都有 $READY$ 记录，发布完整。$pkg\_b$ 的 $ios$ 记录是 $FAIL$，$FAIL$ 不能替代 $READY$，因此仍缺少 $ios$ 的就绪记录。$pkg\_c$ 要求版本为 $v2.0$，而日志里只有 $v1.5$ 的记录，非要求版本不计入，三个平台都缺。按资源计划顺序输出 $pkg\_b$ 与 $pkg\_c$。


## 样例2



**输入** 



```
2 7
pkg_x sceneA build-1
pkg_y sceneA build-1
pkg_x build-1 android FAIL
pkg_x build-1 android READY
pkg_x build-1 ios READY
pkg_x build-1 pc READY
pkg_y build-1 android READY
pkg_y build-1 ios READY
pkg_y build-1 pc READY
```



**输出** 



```
none
```



**说明**

$pkg\_x$ 的 $android$ 平台先有一条 $FAIL$ 再有一条 $READY$，同一资源包同一版本同一平台可以出现多条记录，只要存在至少一条 $READY$ 即算就绪，因此 $pkg\_x$ 三个平台齐全。$pkg\_y$ 三个平台各有一条 $READY$，同样完整。没有任何资源包缺少就绪记录，输出 $none$。
