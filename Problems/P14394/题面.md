# 数据包收发模拟

某网络设备采用收发机制管理数据包，包含**缓冲区**与**发送区**两个区域，按顺序执行若干条指令并输出每条指令的处理结果。

## 指令规则

1. **RECEIVE x**：接收编号为 $x$ 的数据包。
   - 若**缓冲区**中不存在编号 $x$，接收成功，将其按接收顺序加入缓冲区，输出 $x$；
   - 若**缓冲区**中已存在编号 $x$，接收失败，输出 $-1$。
   - 仅检查缓冲区，不检查发送区。

2. **SEND**：发送一个数据包。
   - 若发送区非空，取出其中**最早进入发送区**的数据包发送，输出其编号；
   - 若发送区为空且缓冲区非空，先将缓冲区中**全部**数据包按原顺序依次移入发送区，再取出最早的一个发送并输出其编号；
   - 若两区均为空，输出 $0$。

3. **QUERY**：查询最早接收但尚未发送的数据包编号（不发送）。
   - 若发送区非空，输出发送区中最早的数据包编号；
   - 若发送区为空且缓冲区非空，先将缓冲区中**全部**数据包移入发送区，再输出发送区最早的数据包编号；
   - 若两区均为空，输出 $0$。

评测采用 **LeetCode 核心代码模式**：只需实现 `Solution` 中的方法，平台负责读入与调用。**不要**编写 `main` 或自行处理 stdin/stdout。

## 函数接口

| 语言 | 签名 |
|------|------|
| Python | `def processPacketCommands(self, commands: List[str]) -> List[int]` |
| Java | `public int[] processPacketCommands(String[] commands)` |
| C++ | `vector<int> processPacketCommands(vector<string>& commands)` |

### 参数

- `commands`：长度 $n$ 的字符串数组，每个元素为一条合法指令，格式为 `RECEIVE x`、`SEND` 或 `QUERY`（$x$ 为整数）。

### 返回值

长度为 $n$ 的整数数组/列表，第 $i$ 个元素为第 $i$ 条指令的处理输出。

## 数据范围

- $1 \le n = \texttt{commands.length} \le 100$；
- $1 \le x \le 1000$；
- 输入指令格式保证合法。

## 输入格式（平台侧，选手无需编写）

stdin **一行**：指令字符串数组的 JSON 风格表示，元素用英文双引号，逗号后**不加空格**（与样例字符级一致）：

```text
["RECEIVE 1","RECEIVE 2","QUERY","SEND"]
```

## 输出格式

一行：整数列表的 JSON 风格表示，行末换行。例如 `[1,2,1,1]`。

## 样例 1

**输入**

```text
["RECEIVE 1","RECEIVE 2","QUERY","SEND","QUERY","SEND"]
```

**输出**

```text
[1,2,1,1,2,2]
```

**说明**

- `RECEIVE 1`：缓冲区无 $1$，接收成功，输出 $1$；
- `RECEIVE 2`：缓冲区无 $2$，接收成功，输出 $2$；
- `QUERY`：发送区为空，缓冲区 $[1,2]$ 整体移入发送区，输出最早 $1$；
- `SEND`：发送区弹出 $1$，输出 $1$；
- `QUERY`：发送区剩余 $[2]$，输出 $2$；
- `SEND`：发送并输出 $2$。

## 样例 2

**输入**

```text
["RECEIVE 3","RECEIVE 3","SEND","SEND","SEND"]
```

**输出**

```text
[3,-1,3,0,0]
```

**说明**

- 第二次 `RECEIVE 3` 时缓冲区已有 $3$，输出 $-1$；
- 随后 `SEND` 将缓冲区中的 $3$ 移入发送区并发送；
- 后两次 `SEND` 两区皆空，输出 $0$。

## 样例 3

**输入**

```text
["RECEIVE 1"]
```

**输出**

```text
[1]
```

**说明**

单条接收指令，输出 $1$。
