# 华为非 AI 岗编程题模拟卷

只生成**题面**，不写题解、标程、测例包。题面必须原创包装，**禁止直接搬** `华为机考题汇总` 里的原题。本项目只出**传统算法编程题**，**没有选择题**。

调用时用户会给算法标签和难度，格式见 `华为非AI方向模拟赛出题/编程题出题/READED.md`。

## 交付物

在 `华为非AI方向模拟赛出题/编程题出题/` 下：

```text
{YYYY.M.D}/
  1-第一题/题面.md     # 对应 150 分，题面里不写分数
  2-第二题/题面.md     # 对应 150 分，题面里不写分数
  3-第三题/题面.md     # 对应 300 分，题面里不写分数
```

日期默认 Asia/Shanghai 当天，形如 `2026.9.8`（月、日不补零）。已有同日目录则用 `2026.9.8-2`。用户指定日期则用用户的。

**不要**在题面中写「150 分 / 300 分」。

## 输入（用户每次会给）

读取用户消息；若消息里没有三行规格，则读 `华为非AI方向模拟赛出题/编程题出题/READED.md`。

规格形态：

```text
150分 <算法标签> <简单|中等|困难> <1-10>
150分 <算法标签> <简单|中等|困难> <1-10>
300分 <算法标签> <简单|中等|困难> <1-10>
按照这个要求出三道题的题面
```

缺算法标签：**fatal stop**，不要猜考点。

缺难度时默认：**第一、二题中等，第三题困难**（与非 AI 真场「两道 150 中等 + 一道 300 困难」对齐）。用户写了难度则以用户为准。

## 硬约束

1. 一场 **三道** 编程题：第一、二题对齐 150 分规格，第三题对齐 300 分规格。
2. **第三题整体必须明显重于前两题**：规则更多、步骤更长、或约束更紧。前两题算法核也必须互不相同，不许三道换皮同题。
3. **禁止搬原题**：算法核按用户标签新编；业务壳从业务库随机抽再改写，不得整段复制 `hook`，不得复用原 PID 的规则与样例。
4. 题面格式 **严格** 按 `华为非AI方向模拟赛出题/编程题出题/题面格式.md`（章节名、样例标题、加粗的输入/输出/说明、text 代码块）。
5. 文风对齐 `华为机考题汇总` 的 **非 AI 方向编程题**（传统算法，不是 AI 岗，不是选择题）。细则见 [style.md](style.md)。
6. **去 AI 腔**：禁止「随着…发展」「赋能」「值得注意的是」「小明」；禁止题面剧透算法名；禁止用大模型 / MoE / KV Cache 当包装。
7. 每题至少 **样例1、样例2**；说明用手算把规则走一遍。数字、公式用 LaTeX `$...$`。
8. **禁止很简单的模板题（写死）**：不能出成换皮后就能套经典模板交的题（裸 01 背包、裸 BFS、裸前缀和、裸排序取最大等）。业务壳换了但思考路径仍是「认模板 → 填公式」的，视为不合格，推倒重编。
9. **按难度安排思维难点（写死）**：难点 = 选手必须想对的一步，想错则朴素/套模板会 WA 或 TLE。数量跟规格里的「简单 | 中等 | 困难」走（同一档内 1–10 越大取上限）：
   - **简单**：0～1 个难点（允许只有一个小观察或边界，但仍禁止裸模板）。
   - **中等**：1～2 个难点（前两道 150 分默认落在此档）。
   - **困难**：3～4 个难点（第三道 300 分默认落在此档）。
   难点须在写题面前列清（只进对话汇报，**不要写进题面**）。算难点的例如：两条规则交叉、会打掉「显然做法」的反例、扫描顺序或贪心依据、状态里要多记一个非显然量、数据范围卡死某档复杂度、要构造而非只判定。不算难点的例如：换物件名、加一句业务背景、把课本题改个输入格式。

## 执行步骤

### 1. 抽业务背景（必须跑脚本）

工作区根目录：

```powershell
python "华为非AI方向模拟赛出题/编程题出题/scripts/pick_scenes.py"
```

输出三条互异 `domain` 的 hook。若 `scenes.json` 缺失或为空，先跑：

```powershell
python "华为非AI方向模拟赛出题/编程题出题/scripts/build_scene_bank.py"
```

第一题用 `picked[0]`，第二题用 `picked[1]`，第三题用 `picked[2]`。只借鉴场景类型（仓储 / 依赖 / 地图 / 选址…），**改物件名、改指标名、改叙事**，再套到本题算法核上。

### 2. 定算法核

对每题先写清（可只出现在对话汇报，不要写进题面）：

- 用户标签对应的正解思路与复杂度
- 本题的思维难点清单（条数必须落在该题难度档：简单 0～1、中等 1～2、困难 3～4），并说明若套模板会在哪一步错
- 两道 150 分之间、以及相对 300 分的难度差具体体现在哪
- 样例手算是否闭环

算法核不清楚、难点不够数、或只能写成课本题换皮，就不要写题面。

### 3. 落盘题面

章节名、样例标题、加粗的「输入 / 输出 / 说明」、样例代码块语言 `text`，一律照抄 `题面格式.md`，不要改成「题目描述」或「样例说明」。

顺序固定：`# 题目内容` → `# 输入描述` → `### 约束` → `# 输出描述` → `## 样例1` → `## 样例2`。

背景 2～5 句后立刻给可执行规则。约束写在 `### 约束`。不要把分数、场次、标签写进正文。

### 4. 自检

- [ ] 三份 `题面.md` 非空，章节齐全，各有两个样例
- [ ] 题面未出现 150/300 分字样
- [ ] 未出现原题 PID、未整段复制 hook
- [ ] 第三题明显重于前两题；前两题算法核不同
- [ ] 无 AI 套话、无算法名剧透、无大模型包装
- [ ] 不是裸模板换皮；每题难点条数与该题「简单/中等/困难」相符
