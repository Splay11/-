# 标程生成与在线提交（题面改写 skill 共用）

`problem-statement-restyle-flavor` 与 `problem-statement-restyle-io-preserve` 在题面交付完成后**必须**执行本节。

## 目标

1. 根据**改写后题面的算法核**，在题目目录生成三份标程：`std.cpp`、`Main.java`、`std.py`  
2. 将三份代码**分别提交到网站原题**（同一 `P{pid}`）做正式评测  
3. 向用户反馈每份是否通过；**凡未通过的必须点名语言、状态与首个失败信息**

## 关键约束（防交错）

| 项 | 要求 |
|----|------|
| 算法核 | 与原题 / 改写题一致（同一实例同一答案） |
| **读入写出协议** | **必须严格对齐原题 `题面.md` 的 I/O 结构**（组数、字段顺序、多行格式），因为评测数据在网站原题上 |
| 改写题若改了单组/多组包装（仅 flavor 可能） | 标程**仍按原题协议**读写；不得按改写后的单组样例形态去交 OJ |
| 变量名 | 代码内可用改写题变量风格，不影响评测 |
| Java | 必须 `public class Main` |
| Python | ACM 读入用 `input()` / `print()`；生成标程时勿仅用 `sys.stdin` 替代（与出题 Skill 约定一致） |

## 落盘路径

```text
Problems/P{pid}/std.cpp
Problems/P{pid}/Main.java
Problems/P{pid}/std.py
```

若目录已有同名文件：默认**覆盖为本次按改写核生成的版本**（本流程产物）；若用户明确禁止覆盖，则改用 `std_restyle.cpp` 等新名并在提交时指向新文件。

## 生成要求

- 三语言实现同一算法；先保证能过改写题面中的新样例（可本地手算/跑样例）  
- 再确认 I/O 循环与原题一致（尤其 `T` 组循环、Σ 约束下的多测）  
- **中文注释**：关键步骤须有中文注释，用语对齐**改写后题面**（勿残留原题专有业务词）；与 `problem-statement-restyle-io-preserve` 的「题解与代码注释对齐」节一致  
- 不要提交伪代码或残缺文件

## 提交命令

环境变量与 `utils/README.md` 相同。对每个文件各提交一次：

```powershell
$env:HYDRO_API_UNAME="luti"
$env:HYDRO_API_PASSWORD="lutilutiluti1014lutilutiluti"

python utils/submit_code_and_get_result.py --base-url https://codefun2000.com --domain-id system --pid P{pid} --lang cc.cc14o2 --code-file "Problems/P{pid}/std.cpp"

python utils/submit_code_and_get_result.py --base-url https://codefun2000.com --domain-id system --pid P{pid} --lang java --code-file "Problems/P{pid}/Main.java"

python utils/submit_code_and_get_result.py --base-url https://codefun2000.com --domain-id system --pid P{pid} --lang py.py3 --code-file "Problems/P{pid}/std.py"
```

- `--base-url` 固定 `https://codefun2000.com`  
- 若 `java` 语言键被平台拒绝，按脚本报错改用实际 key，并在回复中注明所用 `--lang`  
- 须等待评测结果返回；不要只提交不查结果

## 反馈格式（强制）

在题面交付之后追加：

```text
标程与提交：
- std.cpp  → {AC / 未通过：状态…；RID…；首个失败点…}
- Main.java → {…}
- std.py   → {…}

未通过列表：
- （若全 AC 则写「无」；否则逐条列出语言与原因）
```

任一语言未通过时：简要判断（I/O 协议错 / 算法错 / 编译错 / 其它），必要时当场修正该语言后**重提该语言**，直到 AC 或向用户说明仍失败的原因与已尝试修复。

## 完成标准

- 三文件均已生成且非空  
- 三语言均已向原题提交并拿到结果  
- 用户能直接看到哪些过了、哪些没过
