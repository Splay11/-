# 业务背景词库

供 `problem-statement-restyle-flavor` 生成题面业务点缀时抽样组合。条目来自仓库 `Problems/` 既有题面业务包装的归纳与泛化，**不是**原题抄录。

## 使用规则（给 Agent）

1. **每次改写前必读本词库**；从下文某一分类中**随机抽 1 个场景**，再从同分类（或相邻分类）抽 **1～2 个对象/动作词条**，拼成 **1～3 句**业务点缀。
2. 业务点缀只服务「读起来像真实工作场景」，**不得**引入新约束、时限、权限或改变算法核。
3. **禁止出现公司名/品牌名**（含华为、阿里、腾讯、字节、百度、美团、京东、小米、OpenAI 等，以及题面里的具体厂商产品名）。用「某团队 / 运维侧 / 产线侧 / 网关侧」等中性称呼。
4. 避免「小苯 / 小红 / Tk」等人名叙事；优先岗位或系统视角。
5. 同一道题若多次改写，应换分类或换词条，避免总用「运维指标序列」。
6. 算法核是离散结构/纯数学时，仍可轻点缀；点缀句删掉后题意须完整自洽。

## 抽样模板

```text
[场景词条] + [对象词条] +（可选）[动作/目标词条]
→ 压缩成 1～3 句，接上真正题意
```

示例：场景「产线质检」+ 对象「读数序列」+ 动作「合并相邻项使非降」→「产线质检得到一条长度为 $n$ 的整型读数序列……」

## 禁用清单（出现则重写点缀）

- 任何真实公司、院校品牌、产品商标
- 「某大厂」「某厂 OD」「华为机考」等指向具体雇主的说法
- 用真人名当主角凑字数（小苯、小红、Tk、小王等）；改岗位/系统视角

## 维护说明

- 新题改写若出现稳定新场景，把**去公司名后的泛化词条**追加到对应分类（或新建分类）。
- 保持「场景 / 对象 / 动作」三列，便于随机组合，不要只堆整段范文。
