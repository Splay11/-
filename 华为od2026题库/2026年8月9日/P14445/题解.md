## 解题思路

本题的核心是**固定长度滑动窗口求最小子数组和**。

由于连续小时数 `hours` 是固定的，我们可以维护一个长度为 `hours` 的滑动窗口，窗口在电价数组上从左向右移动，每次移动时：

- 减去窗口最左侧离开的元素值
- 加上窗口最右侧新进入的元素值

这样可以在 **O(1)** 时间内从上一个窗口的和更新为当前窗口的和，而无需每次重新累加 `hours` 个元素。

具体步骤：
1. 先计算第 0 个窗口（索引 `0` 到 `hours-1`）的元素总和，作为当前最小值，最优起始索引设为 `0`。
2. 从索引 `i = 1` 开始，依次滑动窗口到 `priceRecords - hours`：
   - `curSum = curSum - priceArray[i-1] + priceArray[i+hours-1]`
   - 如果 `curSum < minSum`，更新 `minSum` 和 `bestIdx = i`
   - 使用**严格小于**比较，保证在多个相同最小成本时，返回最早出现的起始索引

算法核心：**固定窗口大小的滑动窗口**，时间复杂度 O(n)，空间复杂度 O(1)。

## 复杂度分析

- **时间复杂度**：O(n)，其中 n = `priceRecords`。初始窗口求和需 O(hours)，滑动过程遍历 `n - hours` 个位置，每次 O(1) 更新，总体 O(n)。
- **空间复杂度**：O(1)，仅使用常数个变量存储当前和、最小和与最优索引，不依赖额外数据结构。

由于 `priceRecords <= 24`，即使暴力枚举每个起始索引的窗口和（O(n * hours)）也能通过，但滑动窗口解法更优雅且体现了算法思维。

class Solution:
    def findBestChargingTime(self, priceRecords: int, hours: int, priceArray: list[int]) -> int:
        # 计算第一个窗口的元素总和
        cur_sum = sum(priceArray[:hours])
        min_sum = cur_sum
        best_idx = 0

        # 滑动窗口：从左向右移动，每次更新当前窗口和
        for i in range(1, priceRecords - hours + 1):
            # 减去离开窗口的元素，加上新进入窗口的元素
            cur_sum = cur_sum - priceArray[i - 1] + priceArray[i + hours - 1]
            # 严格小于才更新，保证相同最小值时保留最早索引
            if cur_sum < min_sum:
                min_sum = cur_sum
                best_idx = i

        return best_idx
