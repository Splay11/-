    // 左指针指向最左边，右指针指向最右边
    let i = 0;
    let j = height.length - 1;

    // 记录最大面积
    let ans = 0;

    while (i < j) {
        // 当前容器的宽度
        const width = j - i;

        // 当前容器的高度由较短的那根柱子决定
        const h = Math.min(height[i], height[j]);

        // 因为面积受短板限制，移动长板不可能让当前高度变大
        if (height[i] < height[j]) {
            i++;
        } else {
            j--;
        }
    }

    // 返回最大水量
    return ans;
};

#code-switcher

上述算法的本质是：固定左端点 `i`，每次让右端点 `j` 从最右边一路往左枚举，计算每一对 `(i, j)` 的面积。
也就是说，我们其实是在$O(n^2)$地枚举“所有可能的左右边界组合”。

既然暴力法是在大量枚举 `(i, j)`，双指针做法是在思考这么一个事情：
**有没有一些状态其实不可能比当前更优，可以直接跳过？**


**break优化**：假设在右指针往左移动的过程中，遇到$height[i] \leq height[j]$  ，那么$j$已经没有必要往左再移动了。 

![](/file/2/jWgLDued2qNMYjDNSxHFw.png)

这是因为**此时$j$是离$i$最远的，且能够让$height[i]$ 顶满的位置**

往后$j$再往左移动，不仅宽度在减少，而高度已经不可能再增加了。

换句话说，此时 ， 两个指针之间的$[i+1,i+2,...,j-1]$ 这些柱子不可能和$i$形成比$i,j$ 所形成的更大的面积了。

#warning-box
**塔子哥的大白话**：这个break优化，它其实就是在及时止损。因为$j$在往$i$逼近的过程中，$i$心里也很着急啊。因为他知道$j$逼近的过程，宽度是在减少的，这个对我们找最大面积很不利的。**我们的唯一希望，就是希望$j$过来的过程中，高度好歹能再高一点**，不然你宽度在降，高度也上不去，那不是一整个完蛋。所以一旦$height[i]$被顶满了，高度已经变成以$i$为左柱的最高值了，那么接下来的过程就没有意义了，因为高度不能升高了，宽度还在降，这还遍历个啥？？

**原地优化**：我们现在再观察上面的代码：

- 外层循环中，左指针 `i` 每次右移一格
- 但内层循环中的右指针 `j`，每次都会重新回到最右边 `n-1`

但其实，左指针从 `i` 变成 `i+1` 之后，右指针**不用回到最右边**，直接留在原地即可。

换句话说，这个优化认为：$i+=1$后，$j$在$[j+1,j+2,...,n]$ 这些位置上不可能和$i+1$形成得了 比$i$去和$[j+1,j+2,...,n]$所形成得更大的面积，所以没必要回到最右边。

这是为什么呢？

我们先把现在已知的大小关系捋一遍：


$height[j] \geq height[i] > height[k] , k \in [j+1,...,n]$


示意图如下所示👇

![](/file/2/4KP3Es6j1Xg3nx_Puj-UI.png =70%x)


那么对$height[i + 1]$分情况讨论：

1 $height[i+1] \geq height[j]$

![](/file/2/6yk-OuXOcyKmSPsrlfCRS.png)


**说明**：$height[i+1]$ 比$height[i]$ 更高，所以 $i+1$和$k,k\in [j+1,j+2,...,n]$ 这些个柱子能构成的高度，和$i$去与$k$ 构成相比， 所产生的高度都是$height[k]$，也就是$j$ 右边那些位置对于$i,i+1$都是短板。而$i+1$更靠右，**宽度不占优势**，自然不需要去遍历$j$右边的柱子了。

**根据暴力算法 ， 我们还没找到 能 顶满 i + 1 的右指针。下一步就是让更短的$j$往左移动**

2.$height[i+1] < height[j]$ ：

![](/file/2/FOkdTQ06KGkmT9c19H6nw.png)

**说明**：此时$i+1$是短板，本来和$i$相比，宽度就不占优势，而高度可能还会比$j$右侧的柱子矮，面积自然不可能更大了。

**这种情况下，根据break优化，算法的下一步就应该是让更短的$i + 1$往右移动**

此时，我们就能解释清楚，为什么$j$没必要回到$n-1$了，**这是因为在第$i$轮的时候，$i$和$k,k \in [j,j+1,...,n]$ 所形成的面积一定大于 $i+1$ 和它们形成的面积。**

#warning-box
**塔子哥的大白话**：这个原地优化，就是在探讨$i,i+1$和$j$右边那些柱子的关系：$i+1$ 它相较于$i$的一个天生劣势就是：$i+1$更靠右，所以它和$j$右边的柱子形成的宽度天然就比$i$和右边的柱子形成的宽度要小一个单位。上面一顿分析发现，不仅宽度更窄，$i+1$和它们所形成的高度也不可能比$i$更高，那还遍历个啥$[j+1,j+2,...,n]$啊？？
#warning-box


总结一下这两个优化，最终我们得出来的结论是：**弄个双指针，哪边短就缩哪边** ， 这就是本题的核心思想。一句话能概括但是背后其实隐藏了许多优化。

或许很多同学第一次接触这种优化的视角，我们再总结一下：

`break` 优化是在说：**固定左端点时，一旦找到最远的、足以成为短板上界的右端点，就可以停止。**

 原地优化是在说：**右端点没必要回头，因为它右边的状态已经被旧的左端点考察过了。**
 最终这两个优化合在一起，就变成了相向双指针。

本题使用了同向双指针的技巧，枚举两个指针之间的面积。每次抛弃更短的那个柱子，向中间逼近，以获得更大面积。

**2.双指针背后的核心思想是？/暴力双重循环和双指针做法是否有关联？**

双指针本质上是在双重暴力循环的基础上进行了两阶段的优化。第一阶段优化是固定左端点时，一旦找到最远的、成为短板上界的右端点后就break。第二阶段优化是右端点不回头，因为它右侧的状态已经被考虑过了。这两个优化组合形成了双指针算法。

**3.本题时间复杂度是多少？**

$O(n)$ , 考虑两个指针往中间逼近，遇到就停止，则$i,j$ 的移动总量为$n$次。
