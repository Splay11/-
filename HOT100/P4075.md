**思路：依旧全排列**

**如果这题没有对角线的限制，本题方案数是一个全排列！ $Q(n \times n) = n!$**

因为考虑每行放一个，总共放$n$行，那么想要位置合法，列数一定要是一个`n`的全排列。

而本题唯一区别在于：**有主副对角线限制**。做了这么多回溯题，不难想到直接在递归的过程中满足这些限制即可。

接下来考虑**主对角线限制**：

考虑从一个坐标$(x_i,y_i)$出发，要找到某一个和它在同一个主对角线上的坐标，那么一定要满足：

要么往**右下走**相同距离：$x_j = x_i + d , y_j = y_i + d$

要么往**左上走**相同距离：$x_k = x_i - d , y_k = y_i - d$ ， 如下图所示：

![](/file/2/15m2pql_1vfRh3et6WJiP.png =70%x)


不难发现，无论我们怎么在这个主对角线上移动，**横坐标和纵坐标总是同时发生相同变化的，$x$变化多少,$y$就得变化多少，不然轨迹就偏离了**。那这个过程中，**$x - y$ 是一定不变的，是个常量**

换句话说，我们可以用$x - y$ 来判断是否在同一主对角线上。



副对角线同理，自行分析。这里用$x + y$  来判断是否在同一主对角线上。



解决了主副对角线的限制，代码就很好写了。

考虑开辟如下几个标记数组:

`col_used` 代表某一列的占用情况

`main_dig_used` 代表某一主对角线的占用情况。 

`anti_dig_used` 代表某一副对角线的占用情况。 

`board` 代表当前棋盘局面。

class Solution:
    def solveNQueens(self, n: int) -> List[List[str]]:
        # result 用来存储所有合法棋盘
        result = []

        # board 表示当前棋盘局面，一开始什么都没放
        board = [['.' for _ in range(n)] for _ in range(n)]

        # col_used 记录哪些列已经放了皇后
        col_used = set()
        # main_diag_used 记录哪些主对角线已经放了皇后，主对角线用 x - y 表示
        main_diag_used = set()
        # anti_diag_used 记录哪些副对角线已经放了皇后，副对角线用 x + y 表示
        anti_diag_used = set()

        def dfs(index):
            # index 表示当前要放第几行的皇后
            if index == n:
                result.append(["".join(row) for row in board])
                return

            # 枚举当前行的每一列
            for j in range(n):
                x = index
                y = j

                # 如果当前列、主对角线、副对角线已经被占用，则不能放
                if j in col_used or x - y in main_diag_used or x + y in anti_diag_used:
                    continue

                # 放置皇后
                board[x][y] = 'Q'
                col_used.add(j)
                main_diag_used.add(x - y)
                anti_diag_used.add(x + y)

                # 继续放下一行
                dfs(index + 1)

                # 回溯，撤销当前皇后
                board[x][y] = '.'
                col_used.remove(j)
                main_diag_used.remove(x - y)
                anti_diag_used.remove(x + y)

        dfs(0)
        return result

void saveBoard(int n, int** returnColumnSizes) {
    // 如果结果数组容量不够，就扩容
    if (resultSize == capacity) {
        capacity *= 2;
        result = (char***)realloc(result, sizeof(char**) * capacity);
        *returnColumnSizes = (int*)realloc(*returnColumnSizes, sizeof(int) * capacity);
    }

    // 保存当前合法棋盘
    result[resultSize] = (char**)malloc(sizeof(char*) * n);
    (*returnColumnSizes)[resultSize] = n;

    for (int i = 0; i < n; i++) {
        result[resultSize][i] = (char*)malloc(sizeof(char) * (n + 1));
        for (int j = 0; j < n; j++) {
            result[resultSize][i][j] = board[i][j];
        }
        result[resultSize][i][n] = '\0';
    }

    resultSize++;
}

void dfs(int index, int n, int** returnColumnSizes) {
    // index 表示当前要放第几行的皇后
    if (index == n) {
        saveBoard(n, returnColumnSizes);
        return;
    }

    // 枚举当前行的每一列
    for (int j = 0; j < n; j++) {
        int x = index;
        int y = j;

        // 主对角线用 x - y 表示，为了避免负数，下标整体加 n - 1
        int mainDiag = x - y + n - 1;
        // 副对角线用 x + y 表示
        int antiDiag = x + y;

        // 如果当前列、主对角线、副对角线已经被占用，则不能放
        if (colUsed[j] || mainDiagUsed[mainDiag] || antiDiagUsed[antiDiag]) {
            continue;
        }

        // 放置皇后
        board[x][y] = 'Q';
        colUsed[j] = 1;
        mainDiagUsed[mainDiag] = 1;
        antiDiagUsed[antiDiag] = 1;

        // 继续放下一行
        dfs(index + 1, n, returnColumnSizes);

        // 回溯，撤销当前皇后
        board[x][y] = '.';
        colUsed[j] = 0;
        mainDiagUsed[mainDiag] = 0;
        antiDiagUsed[antiDiag] = 0;
    }
}

### 面试问答

**1. 本题的核心思路是什么？**

回溯。我们按“一行放一个皇后”的思路，从上到下逐行递归决定皇后放在哪一列。因为每一行只能放一个皇后，所以递归到第 `index` 行时，枚举这一行的每一列，判断当前位置是否会和之前已经放好的皇后冲突。判断冲突主要看三种限制：同列不能有两个皇后，用`col_used`集合记录哪些列已经被占用；主对角线不能冲突，同一条主对角线满足 `x - y` 相同，则用`main_diag_used`集合记录每个棋子的位置的`x-y` ，代表哪些主对角线被占用。接着副对角线不能冲突，同一条副对角线满足 `x + y` 相同，所以同理使用`anti_diag_used`集合来记录副对角线占用情况。

递归的时候用这三个集合来判断该位置是否合法，合法就递归处理下一行；递归回来后再撤销这一列的选择，继续尝试本行别的列。当递归到第 `n` 行时，说明前面 `n` 行都已经成功放置皇后，此时就是一种合法方案。

时间复杂度是$O(n!)$的。但是由于我们有很多限制操作，实际复杂度远低于这个，但是总的还是在阶乘级别的。
