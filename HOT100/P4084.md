**思路:贪心+双指针优化**

和上题的区别在于：需要求出最小的跳跃次数。

一个**暴力贪心**的思路是：

每次在当前跳跃能到达的所有范围$[i,end]$中，找一个能到达的最远距离的下标，将这个下标当作下一次跳跃的目的地，如此往复计算即可。

这里举个实际的例子大家就明白了

```python id="a7j2ks"
class Solution:
    def jump(self, nums: List[int]) -> int:
        n = len(nums)
        if n <= 1:
            return 0

        ans = 0
        end = 0
        idx = 0

        while end < n - 1:
            # 当前能到的范围
            end = min(idx + nums[idx], n - 1)

            right = -1 # 记录这个可行范围里的最远距离
            mx_idx = -1 # 记录这个可行范围里的最远距离所对应的下标，也就是下一次跳跃的目的地

            # 枚举这个区间里的最远距离并找到这个下标
            for i in range(idx, end + 1):
                if right < i + nums[i]:
                    right = i + nums[i]
                    mx_idx = i

            # 跳到对应下标，进行下下一轮
            idx = mx_idx
            ans += 1

        return ans
```

#code-switcher
上述复杂度不够优秀，因为每次枚举时跳跃可行范围$[i,end]$ 区间有重叠，导致重复计算。其实这些重叠的区间的$right$我们已经算出来过了，但是每次计算新的跳跃的时候$right$还是得从$-1$开始👇

![](/file/2/fN9iP2h22FqB4lLq8rYX3.png)



**双指针优化**：为了不进行重复计算，可以将$right$变成一个单调往右移动的指针。每次枚举到`end + 1`之后，跳跃数+1 ，此时$idx$不回再到$max\_id$的位置，而是继续向右扫描，如此往复。

```python
class Solution:
    def jump(self, nums):
        n = len(nums)

        # 如果数组长度小于等于 1，已经在终点，不需要跳跃
        if n <= 1:
            return 0

        # ans 记录最少跳跃次数
        ans = 0
        # end 表示当前这一步能够到达的右边界
        end = 0
        # farthest 表示在当前范围内，下一步能够到达的最远位置
        farthest = 0

        # 不需要遍历最后一个位置，因为到达最后一个位置后就不用再跳了
        for i in range(n - 1):
            # 枚举当前范围内的位置，更新下一步能够到达的最远位置
            farthest = max(farthest, i + nums[i])

            # 如果走到了当前这一步的右边界，说明必须再跳一次
            if i == end:
                ans += 1
                # 将右边界更新为下一步能够到达的最远位置
                end = farthest

        return ans
```

### 面试问答

**1. 本题的核心思路是什么？**

**贪心+双指针**。用两个指针，一个表示当前跳跃覆盖的最远范围，一个表示下一个跳跃能到的最远位置。遍历数组，每次在当前跳跃范围内不断更新‘下一个最远能到的位置’，一旦到达当前范围的末尾，就跳一次，更新当前范围为下一个最远位置。这样保证每次跳都跳到最优位置，同时指针单调向右，不回头，整个过程线性遍历就能算出最少跳跃次数。”
