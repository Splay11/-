**思路**

这题和上一题的区别在于：

1.每个数可以选多次

2.选出来的数字的总和需要恰好为`target`

**每个数可以选多次：**

回想一下，上一题枚举了一个元素的所有可能状态：选或不选。

而本题中，每个元素可能状态是：

选0个，选1个，选2个，...，选$\frac{target}{candidates[i]}$ 个。

> 因为有总和限制，且每个数都是正数，所以一个数不可能选得超过目标值。

**不难想到，上一题是二路递归，而本题是$k$路递归。**

所以在函数中，我们需要用一个循环来枚举选多少个`candidates[index]`来调用递归，同时参数需要额外记录一个当前总和`total`

```python id="j0djg9"
class Solution:
    def combinationSum(self, candidates: List[int], target: int) -> List[List[int]]:
        ans = []

        def dfs(index, total, candidates, curr):
            if index == len(candidates):
                if total == target:  # 如果当前总和等于目标值，添加当前组合到结果列表
                    ans.append(curr)
                return

            rest = target - total  # 计算剩余的目标值
            up = rest // candidates[index]  # 计算当前候选数最多可以使用多少次 , 向下取整

            for i in range(up + 1):  # 从 0 到 up 次使用当前候选数
                dfs(index + 1, total + i * candidates[index], candidates, curr + [candidates[index]] * i)

        dfs(0, 0, candidates, [])  # 从索引 0 开始，初始总和为 0，当前组合为空
        return ans
```

**递归完全体做法！**

上一种写法里，我们在当前层直接做一件事：枚举当前数字选 `0` 个、`1` 个、`2` 个、...

一个更"递归"的思路是：当前层不再一次性决定“选几个”，而是每次只决定一件事：**当前这个数，是再选一个，还是彻底不选了**。

这样一来，原本“选 0 个、1 个、2 个、3 个...”这种多路递归，**就被拆成了递归层数更多的二路递归：**

1.不选这个数了，直接看下一个数

2.选一个这个数，然后**留在当前下标**，下一层再继续决定还要不要再选。

```python
class Solution:
    def combinationSum(self, candidates, target):
        # ans 用来存储所有满足条件的组合
        ans = []
        # curr 表示当前正在构造的组合
        curr = []
        n = len(candidates)

        def dfs(index, total):
            # 如果已经处理完所有候选数
            if index == n:
                # 当前总和等于 target，说明找到一个合法组合
                if total == target:
                    ans.append(curr[:])
                return

            # 不使用当前候选数，直接去看下一个数
            dfs(index + 1, total)

            # 如果再选一个当前候选数不会超过 target
            if total + candidates[index] <= target:
                # 选择当前候选数一次
                curr.append(candidates[index])

                # 当前数可以重复选，所以继续停留在当前下标
                dfs(index, total + candidates[index])

                # 回溯，撤销这次选择
                curr.pop()

        # 从下标 0 开始，当前总和为 0
        dfs(0, 0)
        return ans
```

#code-switcher
**为什么它能等价于循环枚举呢？**

1.直接不选，对应选 `0` 个

2.选 1 次再`index += 1`，对应选 `1` 个

3.选 2 次再`index += 1`，对应选 `2` 个

4.选 3 次再`index += 1`，对应选 `3` 个

...

所以虽然代码里没有显式写 `for i in range(...)`，但递归树会自然把这些情况一层层展开出来。

**所以它是一种充分利用递归性质的做法！**

### 面试问答

**1. 本题的核心思路是什么？**

这道题的核心思路是**回溯**，从左到右依次考虑每个数字。当递归到某个数字时，有两种决策：一种是**不再使用当前数字**，直接去处理下一个数字；另一种是**使用当前数字一次**，然后继续停留在当前位置，下一层再决定要不要继续选它。这样就把所有可能的组合搜索出来。

时间复杂度是所有可行解的长度之和，本题比较难估计精准的复杂度，比较宽松的上界是$O(n * 2^n)$
