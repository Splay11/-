# 题目内容

系统中进程申请内存时，以页（4KB/页）为最小粒度。多次申请与释放后可能产生碎片。为更好利用碎片资源，需要做碎片整理，示意如下：

![](mem_defrag.png)

实现类 `MemMgmtSys`：

- `MemMgmtSys(int num)`：内存大小初始化为 `num` 页；`pageId` 从 0 开始依次编号；初始全部空闲。
- `processMemAlloc(int processId, int size)`：进程 `processId` 申请连续 `size` 页。成功返回起始页号，失败返回 `-1`。保证：已占用未释放的进程不会再次申请。
  - 从最小页号起查找首个长度至少为 `size` 的连续空闲段；找到则直接分配。
  - 若找不到：先做碎片整理，再按同样规则查找；仍不够则失败。
  - **碎片整理**：将当前所有仍占用内存的进程，按「占用页数升序，页数相同则 `processId` 升序」排序后，**紧密排到内存末尾**（高地址一侧）；空闲页集中在低地址一侧。即使整理后总空闲仍不足本次申请，也必须执行整理。
- `processMemFree(int processId)`：释放该进程占用的全部页，置为空闲。保证进程当前确有占用。
- `processMemQuery(int processId)`：返回该进程当前占用区间的起始页号。保证进程当前确有占用。

## 输入描述

每行一次函数调用；首行必为一次 `MemMgmtSys`。累计调用次数不超过 $1000$。

$1\le \textit{size}\le \textit{num}\le 256$，$0\le \textit{processId}\le 10000$。

## 输出描述

按顺序输出每次调用结果；无返回值的调用由框架输出 `null`。

## 样例1

输入：

```
MemMgmtSys(10)
processMemAlloc(0, 3)
processMemAlloc(10, 1)
processMemAlloc(40, 2)
processMemAlloc(30, 1)
processMemAlloc(20, 2)
processMemFree(10)
processMemFree(30)
processMemAlloc(50, 2)
processMemQuery(0)
```

输出：

```
null
0
3
4
6
7
null
null
0
7
```

解释：

多次分配后释放进程 10、30，空闲不连续。`processMemAlloc(50,2)` 触发整理：进程 20、40、0（页数 2、2、3）按规则排在末尾，起始页分别为 3、5、7；低地址空出连续空闲后，进程 50 分到起始页 0。随后查询进程 0 得到 7。

## 样例2

输入：

```
MemMgmtSys(8)
processMemAlloc(50, 1)
processMemAlloc(30, 1)
processMemFree(50)
processMemAlloc(20, 2)
processMemAlloc(10, 3)
processMemFree(20)
processMemAlloc(40, 5)
processMemQuery(10)
processMemFree(30)
processMemAlloc(40, 5)
```

输出：

```
null
0
1
null
2
4
null
-1
5
null
0
```

解释：

申请进程 40 的 5 页时连续空闲不足，仍执行整理；整理后总空闲仍不足，返回 `-1`，但进程 10 已被挪到起始页 5。释放进程 30 后再次申请成功，返回 0。
