### 代码模板

同向双指针指的是，双指针方向同时向一个方向。算法的**正确性依赖问题单调性，单调性是指：对于每个左端点，最优右端点的位置是有序的，所以右指针不用来回移动**

## Leetcode 3.无重复字符的最长子串

[在线刷题](https://codefun2000.com/p/P4007)

[视频讲解](https://www.bilibili.com/video/BV1nR5i6GEms/?spm_id_from=333.1387.homepage.video_card.click&vd_source=0f2b5f5dae4beb99b68547471f7432e0)

给定一个字符串$s$，请你找出其中不含有重复字符的 最长子串 的长度

$abcabcbb \rightarrow 3$

**说明**

因为无重复字符的最长子串是 "$abc$"，所以其长度为 $3$。

### 思路

其实很简单，考虑一个函数:$f(i)$ , 代表 固定左端点$i$，右端点最远能达到的下标，用一个动画来演示一下👇

@[video](https://codefun2000.com/p/3934/file/%E6%97%A0%E9%87%8D%E5%A4%8D%E5%AD%97%E7%AC%A6%E7%9A%84%E6%9C%80%E9%95%BF%E5%AD%90%E4%B8%B2.mp4)


很容易感觉出来，**$f(i)$ 随$i$ 单调非减**，因为$f(i)$ 相较于$f(i-1)$ 而言少了一个`s[i-1]` , 相当于冲突的概率下降了👇

![](/file/2/YDU3BIg_72aCbt4hSNLHn.png =70%x)


答案就是$max(f(1)-1+1,f(2)-2+1,...,f(n)-n+1)$ , 因为这考虑了所有的情况。所以我们如果能对每个$i$都求出$f(i)$ , 取最大值不就完事了。

**双指针呼之欲出**:枚举左端点$i$ , **让右端点$j$找$f(i)$ **,  找到之后$i$ 右移动 ， 右端点基于$f(i)$ 寻找$f(i + 1)$

总结：左端点$i$枚举起点，右端点$j$寻找$f(i)$ 。 两个指针各司其职。不回退的原因是$f$ 单调非减。

```python
class Solution:
    def lengthOfLongestSubstring(self, s: str) -> int:
        # 维护当前窗口中的字符集合
        st = set()
        
        # 获取字符串长度
        n = len(s)
        
        # j 表示当前窗口的右端点
        j = -1
        
        # 记录最长无重复字符子串的长度
        ans = 0
        
        # i 枚举窗口左端点
        for i in range(n):
            # 不断向右扩展 j，直到遇到重复字符或到达字符串末尾
            while j < n - 1 and s[j + 1] not in st:
                st.add(s[j + 1])
                j += 1
            
            # 更新最长无重复字符子串的长度
            ans = max(ans, j - i + 1)
            
            # 左端点右移前，将当前左端点字符从集合中移除
            st.remove(s[i])
        
        # 返回最长无重复字符子串的长度
        return ans
```

### 面试问答

#### 1.这个算法的整体思路是什么？

双指针做法里，左指针 $i$ 负责枚举每个位置作为子串起点，右指针 $j$ 负责在当前左端点下尽量向右扩展，找到最远的不重复子串。
每次求出当前窗口的答案后，再移动左指针继续处理下一个起点。

#### 2.为什么这么做是对的？

这个算法本质上是在枚举每个左端点，并维护对应的最远合法右端点；由于这个右端点随着左端点具有单调性，所以指针无需回退。
也就是说，右指针整体只会单调向右移动，不会漏掉答案，因此时间复杂度是 $O(n)$

#### 思考题

大部分讲解是枚举右端点，缩左端点，其实本质一样，大家自行思考这份代码正确性：

## Leetcode 76.最小覆盖子串

[在线刷题](https://codefun2000.com/p/P4053)

给你两个字符串 `s` 和 `t` 。请你在 `s` 中找出包含 `t` 所有字符的最小子串。如果不存在这样的子串，返回空字符串。

**输入**

```
ADOBECODEBANC
ABC
```

**输出**

```
BANC
```

**注意：**

- `t` 中如果某个字符出现多次，那么子串中也必须至少出现这么多次
- 题目保证答案如果存在，则唯一

------

### 思路

假设`s=abbdac` , `t=aab`  , 最短覆盖子串是`s[1:5] = abbda` 。 

为了更好的实现本题，我们可以将 一个子串`x`是否覆盖`t`  这一问题 转化为 `x` 的所有字符的出现次数 **都大于等于**  `t`中对应的字符出现的次数👇

![](/file/2/6CDZv5pxEgGXOEmmCzU3p.png =80%x)





上一题维护的性质是：窗口内不能有重复字符

而这题维护的性质变成了：**窗口必须包含 `t` 的所有字符，且每个字符的出现次数都不少于 `t`** 

所以这题的基本套路仍然是：

- 右指针不断向右扩展，尝试让当前窗口变成“合法窗口”
- 一旦当前窗口已经合法，就不断右移左指针，尽量缩小窗口
- 在缩小的过程中更新最短答案

一句话:**滑动窗口一旦合法，就立刻缩；缩的过程中更新最优答案。**

```python
class Solution:
    def minWindow(self, s: str, t: str) -> str:
        # 统计 t 中每个字符需要出现的次数
        need = {}
        for ch in t:
            need[ch] = need.get(ch, 0) + 1
        
        # 统计当前窗口中每个字符出现的次数
        window = {}
        
        # 左指针
        i = 0
        
        # 当前满足要求的字符种类数
        valid = 0
        
        # 最优答案的起点
        start = 0
        
        # 记录最短覆盖子串的长度，初始设为不可能达到的值
        min_len = len(s) + 1
        
        # 右指针不断向右扩展
        for j in range(len(s)):
            ch = s[j]
            
            # 右指针加入一个字符，更新窗口信息
            if ch in need:
                window[ch] = window.get(ch, 0) + 1
                
                # 如果当前字符的出现次数恰好达到要求，说明又有一种字符满足条件
                if window[ch] == need[ch]:
                    valid += 1
            
            # 当窗口已经包含 t 的所有字符时，尝试缩小左边界
            while valid == len(need):
                # 先用当前合法窗口更新答案
                if j - i + 1 < min_len:
                    min_len = j - i + 1
                    start = i
                
                # 准备移出左端点字符
                left_ch = s[i]
                if left_ch in need:
                    # 如果移出前这个字符刚好满足要求，那么移出后窗口将不再合法
                    if window[left_ch] == need[left_ch]:
                        valid -= 1
                    
                    # 更新窗口中该字符的出现次数
                    window[left_ch] -= 1
```

```c
char* minWindow(char *s, char *t) {
    // 统计 t 中每个字符需要出现的次数
    int need[256] = {0};

    // 统计当前窗口中每个字符出现的次数
    int window[256] = {0};

    // 记录 t 中一共有多少种不同字符
    int needSize = 0;

    for (int i = 0; t[i] != '\0'; i++) {
        unsigned char ch = t[i];

        // 第一次出现这个字符，字符种类数加一
        if (need[ch] == 0) {
            needSize++;
        }

        need[ch]++;
    }

    // 左指针
    int i = 0;

    // 当前满足要求的字符种类数
    int valid = 0;

    // 最优答案的起点
    int start = 0;

    // 获取字符串 s 的长度
    int n = strlen(s);

    // 记录最短覆盖子串的长度，初始设为不可能达到的值
    int minLen = n + 1;

    // 右指针不断向右扩展
    for (int j = 0; j < n; j++) {
        unsigned char ch = s[j];

        // 右指针加入一个字符，更新窗口信息
        if (need[ch] > 0) {
            window[ch]++;

            // 如果当前字符的出现次数恰好达到要求，说明又有一种字符满足条件
            if (window[ch] == need[ch]) {
                valid++;
            }
        }

        // 当窗口已经包含 t 的所有字符时，尝试缩小左边界
        while (valid == needSize) {
            // 先用当前合法窗口更新答案
            if (j - i + 1 < minLen) {
                minLen = j - i + 1;
                start = i;
            }

            // 准备移出左端点字符
            unsigned char leftCh = s[i];

            if (need[leftCh] > 0) {
                // 如果移出前这个字符刚好满足要求，那么移出后窗口将不再合法
                if (window[leftCh] == need[leftCh]) {
                    valid--;
                }

                // 更新窗口中该字符的出现次数
                window[leftCh]--;
            }

            // 左指针右移，继续尝试缩小窗口
            i++;
        }
    }

    // 用静态数组保存答案，避免返回局部变量地址
    static char ans[1000005];

    // 如果 minLen 没有被更新，说明不存在覆盖子串
    if (minLen == n + 1) {
        ans[0] = '\0';
        return ans;
    }

    // 截取最短覆盖子串
    strncpy(ans, s + start, minLen);
    ans[minLen] = '\0';

    return ans;
}
```

#### 为什么可以这样做？

这题同样依赖单调性。设 $f(i)$ 表示：固定左端点 $i$ 时，第一个能够覆盖 `t` 的最小右端点位置。不难证明：$f(i)$是**单调非降**的。而右端点本质上就是在找这个$f(i)$，所以右端点不用回退，单方向移动即可。这里塔子哥不再展开叙述，写了第一题的同学自行思考。

#### 这题的更新答案为什么要写在while里？

因为 `while valid == len(need)` 说明：**当前窗口已经是一个合法覆盖子串**

但我们要求的是**最短**覆盖子串，所以只要窗口合法，就应该立刻尝试更新答案，然后继续收缩左边界。

### 面试问答

#### 1. 这个算法的整体思路是什么？

使用的是同向双指针。

右指针负责不断向右扩展区间，使窗口包含 `t` 的所有字符。
当窗口已经合法后，左指针继续右移，在保证窗口仍然合法的前提下尽量缩小区间，并在这个过程中更新最短答案。

时间复杂度是：$O(n)$

因为左右指针都只会单调地向右移动，不会回退。

## LeetCode 986. 区间列表的交集
本题来源于华为[面试手撕高频题](https://codefun2000.com/codenote/hot100/P0023)
[在线刷题](https://codefun2000.com/p/P4816)

给定两个由若干个 **闭区间** 组成的列表，分别为 $firstList$ 和 $secondList$。

每个区间列表内部的区间都是两两不相交的，并且已经按照区间起点从小到大排序。

请你求出这两个区间列表的所有交集。

形式上，闭区间 $[a, b]$ 表示所有满足 $a \le x \le b$ 的实数 $x$。

两个闭区间的交集要么为空，要么仍然是一个闭区间。例如，$[1, 3]$ 和 $[2, 4]$ 的交集为 $[2, 3]$。

**输入**

```
4 4
0 2
5 10
13 23
24 25
1 5
8 12
15 24
25 26
```

**输出**

```
6
1 2
5 5
8 10
15 23
24 24
25 25
```

**思路：**

这题第一眼看上去是区间题，但实际上做法非常直接。

因为题目已经把两个区间**列表都排好序了**，并且**每个列表内部互不相交**。这两个条件一给出来，双指针基本就呼之欲出了。

**先想最核心的问题：两个区间什么时候有交集？**

假设现在有两个区间：

$$
[a,b],\quad [c,d]
$$

它们的交集是什么？

其实直接取：

* 左端点取较大值
* 右端点取较小值

也就是：

$$
[\max(a,c),\min(b,d)]
$$

但这个区间不一定存在，只有当

$$
\max(a,c)\le \min(b,d)
$$

时，它们才真的有交集。

比如：

* $[0,2]$ 和 $[1,5]$ 的交集是 $[1,2]$
* $[5,10]$ 和 $[8,12]$ 的交集是 $[8,10]$
* $[0,2]$ 和 $[3,4]$ 没有交集，因为左端点已经比右端点大了

所以这题最基本的结论就是：

> 两个闭区间的交集，直接取左端点最大值、右端点最小值；如果左不超过右，那么这个交集有效。

---

**那么双指针该怎么动？**

设：

* `i` 指向 `firstList` 当前区间
* `j` 指向 `secondList` 当前区间

也就是说，我们每次只看：

* `firstList[i]`
* `secondList[j]`

先判断这两个区间有没有交集，如果有，就把交集加入答案。

接下来关键问题来了：

> 处理完这两个区间后，谁该往后走？

这一步才是整道题的核心。

---

**为什么每次移动右端点更小的那个区间？**

假设当前比较的是：

$$
[a,b],\quad [c,d]
$$

如果 $b<d$，说明第一个区间更早结束。

那第一个区间和第二个区间的交集已经算完了，第一个区间以后**不可能再和 `secondList[j]` 后面的更靠右区间产生更好的重叠机会**，因为它自己已经结束了。

所以这时候应该让第一个区间往后走，也就是 `i += 1`。

同理：

* 如果 $d<b$，就让 `j += 1`
* 如果 $b=d$，两个区间同时结束，移动哪个都可以，通常移动任意一个即可；当然两个都移动也可以

```python
class Solution:
    def intervalIntersection(self, firstList: List[List[int]], secondList: List[List[int]]) -> List[List[int]]:
        # 定义两个指针，分别指向两个区间列表
        i = 0
        j = 0
        
        # 存储所有交集区间
        ans = []

        # 当两个指针都没有越界时，继续比较
        while i < len(firstList) and j < len(secondList):
            # 取出当前两个区间
            a, b = firstList[i]
            c, d = secondList[j]

            # 计算当前两个闭区间的交集
            left = max(a, c)
            right = min(b, d)

            # 如果 left <= right，说明存在交集
            if left <= right:
                ans.append([left, right])

            # 谁的右端点更小，谁先结束，谁就先向后移动
            if b < d:
                i += 1
            else:
                j += 1

        # 返回所有交集区间
        return ans
```

**1. 本题的核心思路是什么？**

利用两个区间列表都已经按起点排序，且各自内部互不相交这一性质，使用同向双指针分别扫描两个列表。每次取当前两个区间，先用 $\max(l_1,l_2),\min(r_1,r_2)$ 判断是否存在交集；如果存在就加入答案。然后比较两个区间的右端点，**谁的右端点更小，谁就先结束，谁的指针就先后移**，因为这个区间不可能再和后面的区间产生新的交集。这样两个指针都只会单调向右移动一次。

```python 
class Solution:
    def findAnagrams(self, s: str, p: str) -> List[int]:
        n, m = len(s), len(p)

        # 如果 s 的长度小于 p 的长度，
        # 那么 s 中不可能存在 p 的异位词子串
        if n < m:
            return []

        cnt_p = [0] * 26   # 统计字符串 p 中每个字母出现的次数
        cnt_s = [0] * 26   # 统计当前滑动窗口中每个字母出现的次数

        for ch in p:
            cnt_p[ord(ch) - ord('a')] += 1

        # 统计 s 的第一个长度为 m 的窗口中每个字符的频次
        for i in range(m):
            cnt_s[ord(s[i]) - ord('a')] += 1

        ans = []   # 用来保存所有满足条件的起始下标

        # 先检查第一个窗口是否和 p 的字符频次完全相同
        if cnt_s == cnt_p:
            ans.append(0)

        # 固定大小滑动窗口：每次向右移动一格
        for i in range(m, n):

            # 说明当前窗口是 p 的一个异位词
            if cnt_s == cnt_p:
```

#### 1.这个算法的整体思路是什么？

这道题的整体思路是：**固定长度滑动窗口 + 哈希表统计频次**。

具体的，先用一个哈希表统计字符串$p$的出现频次。再用一个固定大小的滑动窗口+哈希表去从左往右枚举每一个子串，统计当前子串的字符频次，过程中动态地更新哈希表。

#### 2.这个算法的复杂度是多少？

假设$s,p$的长度都是$n$这个量级 ,则时间复杂度是 $O(n)$ 。 因为窗口小于等于$n$个 ， 而哈希的插入和删除为$O(1) $，对于每个窗口，哈希表的比较次数最多为26次（小写字母的个数）。所以计算次数是$26 * n = O(n)$ ，26这个常数在复杂度中是忽略不计的。

## LeetCode 1423. 可获得的最大点数
本题来源于华为校招面试[手撕高频题](https://codefun2000.com/codenote/hot100/P0023)。

[在线刷题](https://codefun2000.com/p/P4815)

几张卡牌排成一行，每张卡牌都有一个对应的点数。点数由整数数组 $cardPoints$ 给出。

每次操作，你可以从这一行卡牌的最左端或者最右端拿走一张卡牌，最终你必须恰好拿走 $k$ 张卡牌。

你的得分为拿到的这 $k$ 张卡牌点数之和。

现在给定卡牌点数数组 $cardPoints$ 以及整数 $k$，请你求出可以获得的最大点数。

**输入**

```
7 3
1 2 3 4 5 6 1
```

**输出**

```
12
```

**思路：**

这题第一眼看上去像是“每次从左边或者右边选”，很多同学会下意识往模拟、搜索上想。

但这题真正的关键在于：**反着想**。

**正着想不太好做，反着想就很简单**

题目要求我们**恰好拿走 $k$ 张牌**，并且只能从两端拿。

那拿走之后，原数组里会剩下多少张牌？

答案是：$n-k$ 张。

而且注意一个非常关键的性质：

> 由于每次只能从最左边或者最右边拿，所以最后剩下来的牌，一定是原数组中的一段**连续子数组**。

这个结论非常重要。因为你从两边不断拿，最后中间没被拿走的部分，不可能是零散的，只会是一整段连续区间。

所以这题其实等价于：

* 总分固定是整个数组的元素和
* 你最终拿走 $k$ 张牌，等价于**留下 $n-k$ 张连续的牌不拿**
* 要让拿到的分数最大，就要让**留下来的这一段连续子数组的和最小**

于是问题直接转化成：

> 在数组中找到一个长度为 $n-k$ 的连续子数组，使它的元素和最小。

那么答案就是：

$$
\text{sum}(cardPoints)-\text{长度为 }n-k\text{ 的最小连续子数组和}
$$
以样例：

```
7 3
1 2 3 4 5 6 1
```

从图中我们可以总结出做法：

我们维护一个长度为 $n-k$ 的窗口：

* 先统计第一个窗口的和
* 然后窗口每次向右移动一格
* 加入一个新数，移出一个旧数
* 不断维护长度为 $n-k$ 的最小窗口和

```python
class Solution:
    def maxScore(self, cardPoints: List[int], k: int) -> int:
        n = len(cardPoints)
        total = sum(cardPoints)

        # 如果 k == n，说明所有牌都要拿走
        if k == n:
            return total

        window_len = n - k

        # 先统计第一个长度为 window_len 的窗口和
        cur = sum(cardPoints[:window_len])
        min_sum = cur

        # 固定大小滑动窗口：每次向右移动一格
        for i in range(window_len, n):
            cur += cardPoints[i]                  # 新进入窗口的数
            cur -= cardPoints[i - window_len]     # 滑出窗口的数
            min_sum = min(min_sum, cur)

        # 最大得分 = 总和 - 留下来的最小连续子数组和
        return total - min_sum
```

### 面试问答

**1. 本题的核心思路是什么？**

与其考虑“从左右两端怎么拿 $k$ 张牌”，不如考虑“最后会剩下一段长度为 $n-k$ 的连续子数组”。由于总和固定，要让拿到的点数最大，就等价于让这段剩下来的连续子数组和最小。于是问题转化为：求长度为 $n-k$ 的最小连续子数组和。然后使用固定大小滑动窗口在线性时间内解决即可。

**时间复杂度是O(n)**

因为我们先求一次数组总和，再用固定大小滑动窗口扫描一遍数组。整个过程中，每个元素至多参与常数次运算，所以总复杂度是 $O(n)$ 。

**空间复杂度是O(1)**

因为只用了若干额外变量来维护窗口和答案，没有使用额外的线性空间。
