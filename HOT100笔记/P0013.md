## Leetcode 11.盛最多水的容器

[在线刷题](https://codefun2000.com/p/P4004)

给定一个长度为$n$的整数数组$height$ 。有 $n$ 条垂线，第 $i$ 条线的两个端点是 $(i, 0)$ 和 $(i, height[i])$ 。

找出其中的两条线，使得它们与 $x$轴共同构成的容器可以容纳最多的水。

返回容器可以储存的最大水量。

**说明:** 你不能倾斜容器。

**输入** 

```
9
1 8 6 2 5 4 8 3 7
```

**输出** 

```
49
```

双重循环暴力：

一个最直观的想法就是两个循环，枚举任意两个柱子之间所形成的面积。我们先看看这段代码，**暴力做法和双指针做法只差临门一脚**：

#code-switcher
```python
from typing import List

class Solution:
    def maxArea(self, height: List[int]) -> int:
        n = len(height)
        ans = 0

        for i in range(n):                 # 左指针从左到右
            for j in range(n - 1, i, -1):  # 右指针从右到左，且保证 j > i
                # 两个柱子之间的面积由两个柱子之间较短的那个确定
                area = (j - i) * min(height[i], height[j])
                ans = max(ans, area)

        return ans
```

```javascript
var maxArea = function(height) {
    // 左指针指向最左边，右指针指向最右边
    let i = 0;
    let j = height.length - 1;

    // 记录最大面积
    let ans = 0;

    while (i < j) {
        // 当前容器的宽度
        const width = j - i;

        // 当前容器的高度由较短的那根柱子决定
        const h = Math.min(height[i], height[j]);

        // 计算当前面积并更新答案
        ans = Math.max(ans, width * h);

        // 哪边更短，就移动哪边
        // 因为面积受短板限制，移动长板不可能让当前高度变大
        if (height[i] < height[j]) {
            i++;
        } else {
            j--;
        }
    }

    // 返回最大水量
    return ans;
};
```

#code-switcher

上述算法的本质是：固定左端点 `i`，每次让右端点 `j` 从最右边一路往左枚举，计算每一对 `(i, j)` 的面积。
也就是说，我们其实是在$O(n^2)$地枚举“所有可能的左右边界组合”。

既然暴力法是在大量枚举 `(i, j)`，双指针做法是在思考这么一个事情：
**有没有一些状态其实不可能比当前更优，可以直接跳过？**


**break优化**：假设在右指针往左移动的过程中，遇到$height[i] \leq height[j]$  ，那么$j$已经没有必要往左再移动了。 

![](/file/2/jWgLDued2qNMYjDNSxHFw.png)

这是因为**此时$j$是离$i$最远的，且能够让$height[i]$ 顶满的位置**

往后$j$再往左移动，不仅宽度在减少，而高度已经不可能再增加了。

换句话说，此时 ， 两个指针之间的$[i+1,i+2,...,j-1]$ 这些柱子不可能和$i$形成比$i,j$ 所形成的更大的面积了。

#warning-box
**塔子哥的大白话**：这个break优化，它其实就是在及时止损。因为$j$在往$i$逼近的过程中，$i$心里也很着急啊。因为他知道$j$逼近的过程，宽度是在减少的，这个对我们找最大面积很不利的。**我们的唯一希望，就是希望$j$过来的过程中，高度好歹能再高一点**，不然你宽度在降，高度也上不去，那不是一整个完蛋。所以一旦$height[i]$被顶满了，高度已经变成以$i$为左柱的最高值了，那么接下来的过程就没有意义了，因为高度不能升高了，宽度还在降，这还遍历个啥？？
#warning-box

**原地优化**：我们现在再观察上面的代码：

- 外层循环中，左指针 `i` 每次右移一格
- 但内层循环中的右指针 `j`，每次都会重新回到最右边 `n-1`

但其实，左指针从 `i` 变成 `i+1` 之后，右指针**不用回到最右边**，直接留在原地即可。

换句话说，这个优化认为：$i+=1$后，$j$在$[j+1,j+2,...,n]$ 这些位置上不可能和$i+1$形成得了 比$i$去和$[j+1,j+2,...,n]$所形成得更大的面积，所以没必要回到最右边。

这是为什么呢？

我们先把现在已知的大小关系捋一遍：


$height[j] \geq height[i] > height[k] , k \in [j+1,...,n]$


示意图如下所示👇

![](/file/2/4KP3Es6j1Xg3nx_Puj-UI.png =70%x)


那么对$height[i + 1]$分情况讨论：

1 $height[i+1] \geq height[j]$

![](/file/2/6yk-OuXOcyKmSPsrlfCRS.png)


**说明**：$height[i+1]$ 比$height[i]$ 更高，所以 $i+1$和$k,k\in [j+1,j+2,...,n]$ 这些个柱子能构成的高度，和$i$去与$k$ 构成相比， 所产生的高度都是$height[k]$，也就是$j$ 右边那些位置对于$i,i+1$都是短板。而$i+1$更靠右，**宽度不占优势**，自然不需要去遍历$j$右边的柱子了。

**根据暴力算法 ， 我们还没找到 能 顶满 i + 1 的右指针。下一步就是让更短的$j$往左移动**

2.$height[i+1] < height[j]$ ：

![](/file/2/FOkdTQ06KGkmT9c19H6nw.png)

**说明**：此时$i+1$是短板，本来和$i$相比，宽度就不占优势，而高度可能还会比$j$右侧的柱子矮，面积自然不可能更大了。

**这种情况下，根据break优化，算法的下一步就应该是让更短的$i + 1$往右移动**

此时，我们就能解释清楚，为什么$j$没必要回到$n-1$了，**这是因为在第$i$轮的时候，$i$和$k,k \in [j,j+1,...,n]$ 所形成的面积一定大于 $i+1$ 和它们形成的面积。**

#warning-box
**塔子哥的大白话**：这个原地优化，就是在探讨$i,i+1$和$j$右边那些柱子的关系：$i+1$ 它相较于$i$的一个天生劣势就是：$i+1$更靠右，所以它和$j$右边的柱子形成的宽度天然就比$i$和右边的柱子形成的宽度要小一个单位。上面一顿分析发现，不仅宽度更窄，$i+1$和它们所形成的高度也不可能比$i$更高，那还遍历个啥$[j+1,j+2,...,n]$啊？？
#warning-box


总结一下这两个优化，最终我们得出来的结论是：**弄个双指针，哪边短就缩哪边** ， 这就是本题的核心思想。一句话能概括但是背后其实隐藏了许多优化。

```python
from typing import List


class Solution:
    def maxArea(self, height: List[int]) -> int:
        # 获取数组长度
        n = len(height)
        
        # 定义左右指针
        i, j = 0, n - 1
        
        # 记录最大盛水面积
        ans = 0
        
        # 当左右指针没有相遇时，继续计算
        while i < j:
            # 两个柱子之间的面积由较短的柱子高度决定
            area = (j - i) * min(height[i], height[j])
            
            # 更新最大面积
            ans = max(ans, area)
            
            # 移动较短柱子对应的指针
            if height[i] <= height[j]:
                i += 1
            else:
                j -= 1
        
        # 返回最大盛水面积
        return ans
```

或许很多同学第一次接触这种优化的视角，我们再总结一下：

`break` 优化是在说：**固定左端点时，一旦找到最远的、足以成为短板上界的右端点，就可以停止。**

 原地优化是在说：**右端点没必要回头，因为它右边的状态已经被旧的左端点考察过了。**
 最终这两个优化合在一起，就变成了相向双指针。

**2.双指针背后的核心思想是？/暴力双重循环和双指针做法是否有关联？**

双指针本质上是在双重暴力循环的基础上进行了两阶段的优化。第一阶段优化是固定左端点时，一旦找到最远的、成为短板上界的右端点后就break。第二阶段优化是右端点不回头，因为它右侧的状态已经被考虑过了。这两个优化组合形成了双指针算法。

**3.本题时间复杂度是多少？**

$O(n)$ , 考虑两个指针往中间逼近，遇到就停止，则$i,j$ 的移动总量为$n$次。

![](/file/2/mZ7eRsVyvotSvnDxVoUvQ.png)

基于上一题的双指针做法，我们在这个过程中，动态维护一个变量$left\_max$ 和  $right\_max$ 分别代表此刻左指针$i$之前和右指针$j$之后的最大高度。

在向中间逼近的过程中，依旧是让更短的柱子那边的指针往中间走。指针在移动之前将它所指向的柱子的答案计算累加即可，这样指针相遇的时候每一个柱子都会被计算到。

```python
from typing import List


class Solution:
    def trap(self, height: List[int]) -> int:
        # 获取数组长度
        n = len(height)
        
        # 双指针，分别指向最左端和最右端
        i, j = 0, n - 1
        
        # left_max 表示左侧目前最高柱子，right_max 表示右侧目前最高柱子
        left_max, right_max = 0, 0
        
        # 记录最终接到的雨水总量
        ans = 0
        
        while i < j:
            # 先更新左右两侧的最高柱子
            left_max = max(left_max, height[i])
            right_max = max(right_max, height[j])
            
            # 哪边更矮，就先结算哪边
            if height[i] < height[j]:
                # 左边这一格能接的水量 = 左侧最高柱子 - 当前柱子高度
                ans += left_max - height[i]
                i += 1
            else:
                # 右边这一格能接的水量 = 右侧最高柱子 - 当前柱子高度
                ans += right_max - height[j]
                j -= 1
        
        return ans
```

**为什么这样移动双指针是对的？**

观察一下：某一位置能接的雨水量是：$ans_i=min(left\_max_i,right\_max_i)−当前位置高度$

这里的唯一问题是我们还无法确定哪边更短，但一旦我们知道当前了$left\_max_i$和$right\_max_i$的大小关系之后，这个值可以被唯一确定了。

想象一下，如果当前 `height[i] < height[j]`，说明左边这一侧更矮

**结论**：此时的$height[j]$是要大于所有的$height[k],k\in[1,2,...,i-1]$的

此时$min(left\_max_i,right\_max_i)=left\_max_i$ , 所以可以确定$ans_i$ ，计算之后$i$往右移动即可。如下图所示

![](/file/2/ebGUARSvnLXRoK0uxWiKz.png)


**说明**：虽然$height[j]$ 并不一定就是$right\_max_i$ ,或许$[i+1,j-1]$ 之间存在更高的柱子，但是计算$ans_i$并不是要去同时得到$i$左右两边的最高点。我们只需要找到更小的那边的值就能算答案。而$height[j] > height[i]$ 就已经能够说明$left\_max_i < height[j]$了 (反过来想想，如果$left\_max_i$更大，那左指针就不会跑到后面的那个比$height[j]$小的地方去了。) ，  

这个结论是对称成立的，所以移动模式是：**哪边短缩哪边**。而且我们也知道，指针移动的那一刻，答案是能够被确定的。

## Leetcode 15.三数之和

```
-1 0 1
```

### 思路:枚举+相向双指针

**本题整体的思路是：先排序，然后枚举三个下标中的某一个下标，剩下的两个下标由相向双指针确定。**

**枚举**：本题枚举$i,j,k$任意一个下标都可以得到正确的答案，这里固定$i$，

外层循环枚举$i$ ，接着需要在$[i+1,n]$ 这个范围里找两个下标$j,k$使得$num[j]+num[k]=-num[i]$ 。

**双指针**：根据上一个小节我们所学习到的双指针技巧，不难想到一种相向双指针算法:令$j=i+1,k=n$

**一句话概括**：当$num[j]+num[k] < -num[i]$ 时, $j += 1$ ， 反之$k -= 1$ 。

思想：当总和小于目标值$-num[i]$ 时，需要移动左指针让总和变大，反之移动右指针让总和变小。

注意：数组可能有重复数字，遍历过程中忽略重复的$num[i]$

```python id="p2xg8h"
class Solution:
    def threeSum(self, nums: list[int]) -> list[list[int]]:
        # 获取数组长度
        n = len(nums)
        
        # 先排序，方便后面使用相向双指针
        nums.sort()
        
        # 用来保存所有不重复的三元组
        ans = []

            if i > 0 and nums[i] == nums[i - 1]:
                continue
```

```go id="z0b6rk"
			continue
		}

		// 在区间 [i + 1, n - 1] 内用相向双指针寻找另外两个数
		j, k := i+1, n-1

		for j < k {
			// 计算当前三数之和
			sum := nums[i] + nums[j] + nums[k]

			if sum == 0 {
				// 找到一组三元组
				ans = append(ans, []int{nums[i], nums[j], nums[k]})

				// 左右指针同时收缩，继续寻找下一组
				j++
				k--

				// 跳过重复的 nums[j]
				for j < k && nums[j] == nums[j-1] {
					j++
				}

				// 跳过重复的 nums[k]
				for j < k && nums[k] == nums[k+1] {
					k--
				}
			} else if sum < 0 {
				// 和太小，需要让总和变大
				j++
			} else {
				// 和太大，需要让总和变小
				k--
			}
		}
	}

	return ans
}
```

```c
#include <stdlib.h>

static int cmp(const void* a, const void* b) {
    return (*(int*)a) - (*(int*)b);
}

int** threeSum(
    int* nums,
    int numsSize,
    int* returnSize,
    int** returnColumnSizes
) {
    // 初始化返回结果
    *returnSize = 0;
    
    int capacity = 16;
    int** ans = (int**)malloc(sizeof(int*) * capacity);
    *returnColumnSizes = (int*)malloc(sizeof(int) * capacity);
    
    // 先排序，方便后面使用相向双指针
    qsort(nums, numsSize, sizeof(int), cmp);
    
    // 枚举第一个数
    for (int i = 0; i < numsSize; i++) {
        // 如果 nums[i] 和前一个数相同，说明会得到重复答案，直接跳过
        if (i > 0 && nums[i] == nums[i - 1]) {
            continue;
        }
        
        // 在区间 [i + 1, numsSize - 1] 内用相向双指针寻找另外两个数
        int j = i + 1;
        int k = numsSize - 1;
        
        while (j < k) {
            long long sum = (long long)nums[i] + nums[j] + nums[k];
            
            if (sum == 0) {
                // 扩容
                if (*returnSize == capacity) {
                    capacity *= 2;
                    ans = (int**)realloc(ans, sizeof(int*) * capacity);
                    *returnColumnSizes = (int*)realloc(
                        *returnColumnSizes,
                        sizeof(int) * capacity
                    );
                }
                
                // 保存一组三元组
                ans[*returnSize] = (int*)malloc(sizeof(int) * 3);
                ans[*returnSize][0] = nums[i];
                ans[*returnSize][1] = nums[j];
                ans[*returnSize][2] = nums[k];
                (*returnColumnSizes)[*returnSize] = 3;
                (*returnSize)++;
                
                // 左右指针同时收缩，继续寻找下一组
                j++;
                k--;
                
                // 跳过重复的 nums[j]
                while (j < k && nums[j] == nums[j - 1]) {
                    j++;
                }
                
                // 跳过重复的 nums[k]
                while (j < k && nums[k] == nums[k + 1]) {
                    k--;
                }
            } else if (sum < 0) {
                // 和太小，需要让总和变大
                j++;
            } else {
                // 和太大，需要让总和变小
                k--;
            }
        }
    }
    
    return ans;
}
```

### 面试问答

**1.这道题的整体思路是什么？**

这道题的整体思路是：**先排序，再枚举一个数，把问题转化成有序数组中的两数之和问题，最后用相向双指针解决。**

**2.这道题双指针背后的思想/为什么双指针是对的？**

双指针之所以正确，是因为排序+枚举后，左指针右移会使和变大，右指针左移会使和变小，搜索具有单调性。

**3.这道题的时间复杂度是多少？**

时间复杂度是$O(n^2)$ ，外层循环枚举$i$ 有$n$ 次， 内层循环的双指针$j,k$相对着移动，总移动量有$n$次。根据分步相乘的思想，复杂度是$O(n \times n) = O(n^2)$

**4.除了双指针的做法，还有没有别的做法？**

有，比较直接的替代做法是：**枚举一个数后，用哈希表做两数之和。** 具体请见哈希章节中的

该做法的时间复杂度一样，但空间复杂度稍微差一些，因为哈希表需要开辟空间，额外占用$O(n)$的空间
