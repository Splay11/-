# Problem Generator Skill

本 Skill 用于创建题目工作目录，整理题面、标准程序、题解与测试数据，并在可能时完成验题。

默认路径：用户提供 **PID**，从 CodeFun2000 抓取题面，再生成 `std.cpp` / `std.py` / `Main.java`、题解与数据。

**兼容路径**：用户在对话中**显式提供**以下任一内容时，以用户内容为优先，**不再**对同一项做「凭空生成」替代：

| 用户显式提供 | 行为 |
|-------------|------|
| 题面（`题面.md` 全文或等价附件/粘贴块） | 不依赖 PID 抓取；将规范化落盘为题目目录下的 `题面.md` |
| 标程（`std.cpp` / `std.py` / `Main.java` 任一或多项） | 对应语言**直接使用用户文件**；未提供的语言仍可按题面与已有标程**补全**其他语言实现（若用户禁止补全，须在新消息中说明） |
| 题解（`题解.md`） | 以题解思路为主生成或对齐标程与造数逻辑；题解内若含可运行代码，**优先采用**为对应语言的 std，并做编译与题意一致性校验 |

本 Skill 仍依赖环境中的 **`algorithm-contest-problemsetter` Skill**，以及工作目录下的本地文件（见下文）。**缺一项关键依赖或关键步骤失败时，进入 fatal stop，只列原因并中止**（见第 0 节）。

---

## 0. Fatal Stop 原则

本 Skill 必须采用 **fail closed** 策略。

### 0.1 何时必须 fatal stop

在**已根据第 1 节确定题面来源、标程来源、题解来源**之后，若任意阶段出现以下情况之一：

- 依赖的 `algorithm-contest-problemsetter` Skill 不存在
- 依赖文件不存在（见 1.3）
- **题面不可用**：既未提供有效 PID 抓取路径，也未在对话中提供可用题面，或抓取失败且用户未提供题面
- 题面落盘后 `题面.md` 不存在或为空
- **标程不可用**：按第 6 节规则，需要的 std 仍缺失、为空或编译/运行失败且无法修复
- **题解不可用**：流程要求生成题解但用户未提供且模板/规范缺失导致无法生成
- 生成数据失败，或数据不符合 `1.in` / `1.out`、… 连续单整数编号规范（若 `algorithm-contest-problemsetter` Skill 另有约定从其约定）
- 验题所需文件缺失（见第 9 节）

必须立即进入 fatal stop 模式。

### 0.2 fatal stop 输出格式

只允许输出缺失或失败原因，不允许继续执行原任务。

```text
无法继续执行，缺失以下依赖或前置条件：

- <缺失项或失败项 1>
- <缺失项或失败项 2>

请手动补充或修复后重新发起任务。
```

输出后必须立即中止当前 workflow。

### 0.3 严格禁止（fatal stop 前后均适用）

- 伪造用户未提供的题面
- 在用户已提供某语言 std 的情况下，**用自生成内容覆盖**该语言的文件（除非用户在新消息中明确要求覆盖）
- 跳过依赖检查
- 发现用户题解/代码与题面明显不一致时**静默忽略**（必须提醒，见第 1.5、7 节）

## 1. 强制前置检查与输入判定

执行任何落盘或生成前，必须先完成本节判定。

### 1.1 题面来源（二选一或组合）

**判定顺序：**

1. **显式题面**：用户在当前任务消息中明确提供了完整或可编辑的题面正文（例如附件名为 `题面.md`，或代码围栏/长文本标明为题目描述）。视为「用户给定题面」。
2. **否则**：用户必须提供 **PID**，并通过 `utils/get_problem.py` 抓取题面。

**规则：**

- 若**已有显式题面**，**不要求** PID；不得因「未提供 PID」而 fatal stop。
- 若无显式题面且无 PID，fatal stop，缺失项写：`未提供题面（无 PID 且无显式题面.md）`。
- 若有 PID 且**同时**有显式题面：以**显式题面为准**写入 `题面.md`；若二者差异较大，在继续前用简短列表提示「题面与 PID 抓取结果不一致，已采用对话中的题面」。

### 1.2 标程（std）来源

对每个语言分别判定：

- 若用户在对话中**显式给出**该语言的完整源码（`std.cpp` / `std.py` / `Main.java`），则该文件**以用户版本为最终标程**，本 Skill **不得**再对该文件做「重新生成式」覆盖。
- 用户**未给出**的语言：在需要三份标程对齐验题时，应基于题面 + 已有用户标程（或题解中的代码）**补全**；若无法安全补全，fatal stop 并说明缺哪一语言及原因。

**Java**：用户提供的 `Main.java` 必须为 `public class Main`，否则 fatal stop 或要求用户修正（类名错误须明确写出）。

### 1.3 题解来源

- 若用户**显式提供** `题解.md`（附件或完整正文）：  
  - 将其作为**思路与实现线索**的权威来源之一；  
  - 若其中含 C++/Python/Java 代码块且语义完整，**优先**采用为对应 std（须通过编译与样例自检）；  
  - 生成数据与验题逻辑须与**最终采用的标程**一致。
- 若用户**未提供**题解：按原流程使用 `题解模板.md` 与 `题解生成规范.md` 生成 `题解.md`；若模板/规范缺失，fatal stop（见 1.4）。

### 1.4 检查依赖 Skill

本 Skill 依赖 `algorithm-contest-problemsetter` Skill。必须检查其是否存在（Skills 列表或下列路径之一）：

```text
.cursor/skills/algorithm-contest-problemsetter/SKILL.md
.cursor/skills-cursor/algorithm-contest-problemsetter/SKILL.md
~/.cursor/skills/algorithm-contest-problemsetter/SKILL.md
~/.cursor/skills-cursor/algorithm-contest-problemsetter/SKILL.md
```

不存在则 fatal stop，缺失项：`依赖的 algorithm-contest-problemsetter Skill 不存在`。

### 1.5 用户内容一致性审查（强制）

在采用**用户题解**或**用户标程**继续造数、验题之前，必须进行**只读审查**；发现问题时**不得假装通过**，须在对话中**明确列出问题类别与建议**：

| 类别 | 说明 |
|------|------|
| 逻辑 | 与题面约束、目标（如最优化方向、边界）矛盾或证明不完整 |
| 编译 | 无法在当前约定环境下编译（缺头文件、语法、类名等） |
| 货不对板 | 代码明显解决的是另一题、变量/模型与题面不符、样例推导不一致 |
| 不完整 | 仅片段、依赖未给出外部模块 |

- **严重问题**（无法得到可信 std 或会误导数据）：须 fatal stop，并在列表中写清原因。  
- **可修复小问题**（如缺 `#include`、明显笔误）：可在一轮中修复并**说明修改点**；若用户禁止改标程，则 fatal stop 并请用户自行修正。

### 1.6 检查依赖文件

必须检查当前工作目录下是否存在：

```text
utils/get_problem.py
题解模板.md
题解生成规范.md
```

**例外**：若用户已提供**完整可用**的 `题解.md` 且本任务**不要求**按模板重新撰写题解（仅对齐格式可选），则「题解模板/规范缺失」可**不**作为 fatal stop 的唯一理由；但若仍需自动生成题解且模板缺失，仍须 fatal stop。

若需要 **PID 抓取**而 `utils/get_problem.py` 缺失，须 fatal stop。

任意其他缺失文件按 0.2 格式列出实际缺失项后中止。

### 1.7 utils 环境与依赖（README）

- **必须先**阅读并执行 **`utils/README.md`** 中的配置与安装步骤（含环境变量、依赖包安装等），完成后对应步骤；
- 仅当已严格按 `utils/README.md` 操作仍无法解决时，再按第 0 节 fatal stop，并在原因中写明「已按 README 仍失败」的具体信息（不得跳过 README 直接中止）。

## 3. 创建题目目录

### 3.1 目录名

- 用户提供了 **PID**：文件夹名为 `P` + PID，例如 PID `1001` → `P1001`（下文「题目目录」即此路径）。
- 用户**未提供 PID**（仅用显式题面）：目录名由用户在消息中指定则用之；否则使用 `P_custom` 或从题面标题抽取简短英文/拼音 slug（仅字母数字与下划线），**不得**与已有目录静默覆盖；若冲突则在后缀加 `_2` 等。

后续所有题目相关文件放在该目录下。

### 3.2 PID 抓取路径下的创建顺序（强制）

当题面来源为 **PID + `get_problem.py`**，且第 1.6、1.7 节已确认脚本存在、环境变量与依赖可按 `utils/README.md` 正常使用时，**不得**先执行脚本再在别处落盘；须严格按下列顺序执行：

1. **立即**创建题目目录 `<题目目录>/`（即 `P{PID}/`），若已存在则复用该目录，**不得**静默覆盖已有非空 `题面.md`（除非用户在新消息中明确要求覆盖）。
2. **立即**在该目录下创建 `题面.md`（可先为空文件或仅占位一行，以保证路径存在）。
3. **再**执行 `utils/get_problem.py`（按 `utils/README.md` 约定传入 PID 等参数）。
4. 将脚本**返回内容**（标准输出、或 README/脚本约定的输出文件）**写入**已存在的 `<题目目录>/题面.md`，覆盖占位内容。

若第 1 步因权限等无法创建目录，fatal stop 并写明原因；**禁止**在未创建目录与 `题面.md` 的情况下仅把抓取结果留在对话中冒充已落盘。

## 4. 题面落盘

### 4.1 使用 PID 抓取

当且仅当**未**采用显式题面作为主来源时：

- 执行顺序与目录要求见 **第 3.2 节**。
- 调用：`utils/get_problem.py`（参数与环境以 `utils/README.md` 与脚本为准）。

将脚本产出保存为：

```text
<题目目录>/题面.md
```

#### 4.1.1 编码与落盘（强制）

脚本返回的字节流**可能不是 UTF-8**（例如 GBK、GB2312、UTF-8 with BOM、平台默认 ANSI 等）。Agent **必须**负责解码与再编码，保证最终写入磁盘的 `题面.md` 为 **UTF-8**（建议无 BOM，与常见工具链一致；若项目统一要求 UTF-8 BOM 则从项目约定）。

**最低要求：**

- 不得以「乱码」或「无法解码」为由跳过落盘；须尝试合理探测或按序尝试常见编码后，再解码为 **Unicode 字符串**，最后以 **UTF-8** 写入 `题面.md`。
- 可行策略（任选其一或组合，以实际环境为准）：使用 Python `charset_normalizer` / `chardet` 检测；或依次尝试 `utf-8`、`utf-8-sig`、`gbk`、`gb2312`、`cp936`、`latin-1`（仅作兜底，须意识到可能误码）；若脚本将结果写入临时文件，则对**文件原始字节**同样做上述处理。
- 若只能启发式解码，在对话中用一句话注明「编码已按某规则推断为 UTF-8 落盘」，**不得**把未转换的原始非 UTF-8 字节直接当作文本粘贴进 `题面.md`。

### 4.2 使用用户显式题面

将用户提供的正文整理为规范 Markdown，写入：

```text
<题目目录>/题面.md
```

### 4.3 校验

若 `题面.md` 不存在或为空，fatal stop：`题面.md 未成功生成或内容为空`。

不得编造题面。

### 6.3 完整性检查

### 6.4 Python 标程（`std.py`）与 NumPy 使用约束

**适用范围**：本节仅在**由本 Skill 生成或补全** `std.py` 时适用。若用户已按第 6.1 节提供 `std.py`，**不得**为贯彻本节而改写其依赖策略（仅可在第 1.5 节框架下做最小必要编译修复）。

**应使用 NumPy（`import numpy as np`）的典型情形**——题意涉及大量**数值线性代数**、**张量式前向/反向**、或纯标准库实现**明显冗长易错**、且**不属于**「力扣式传统算法模板题」时，标程 Python 侧优先用 NumPy 表达核心计算，例如：

- 矩阵乘法、求逆、特征分解、批量线性方程组等**显式矩阵运算**；
- **反向传播**、梯度对权重/偏置的累积、多层可微网络的手工实现；
- **线性回归**闭式解或正规方程、带矩阵形式的损失与梯度；
- 手写 **LSTM / GRU**、**注意力（Attention / QKV / Softmax 权重）** 等需稳定向量化的单元。

**不应为了「用 NumPy」而引入 NumPy 的典型情形**——算法核心仍是离散结构、排序统计、图论、贪心、背包等，用标准库与手写循环即可清晰实现时，**保持零 NumPy**。特别地，下列情形**默认不用 NumPy**（与「手写矩阵」相比，上 NumPy **没有实质简化**）：

- **决策树**（划分、增益、剪枝等离散规则）；
- **K-Means**、**KNN** 等以距离与索引为主、用列表/字典/ `heapq` 等即可自然表达的逻辑。

**判断口诀**：若去掉 NumPy 后主要痛苦来自「**易错的稠密线性代数与张量微分**」，则用 NumPy；若痛苦主要来自「**循环与索引逻辑**」且 NumPy 不会明显减少公式错误面，则不用 NumPy。

**依赖说明**：生成或补全的 `std.py` 若使用 NumPy，须在题解或文件头注释中注明评测环境需提供 NumPy（与 OJ / `algorithm-contest-problemsetter` Skill 约定冲突时，以 OJ 与 `algorithm-contest-problemsetter` Skill 为准，必要时 fatal stop 或改用 C++/Java 标程为造数基准）。

### 6.5 Python 标程输入输出（`std.py`）

**适用范围**：与第 6.4 节相同——仅在**由本 Skill 生成或补全** `std.py` 时强制；用户已按第 6.1 节提供的 `std.py` 不得以贯彻本节为由整文件替换（仅可在第 1.5 节框架下做最小必要修复，并在审查中可提示其与下文规范不一致）。

**强制约定**：

- **严禁**使用 `import sys` 仅为读入标准输入（以及禁止以 `sys.stdin` / `sys.stdin.buffer` / `sys.stdin.readline` 等替代「朴素」读入的惯用写法）。
- 读入使用标准库的 **`input()`**（及由此组合的循环、列表推导等）处理 ACM 模式输入。
- 写出使用 **`print()`** 处理标准输出（多行可多次 `print`，或按题意格式化后 `print`）。

若题面或目标 OJ 对换行符、二进制流有**明文**特殊要求且与 `print` 冲突，在对话与题解中说明例外依据；否则默认遵守本节。

**（与 `leetcode-core-code-mode` 协作）**：当题目以 **LeetCode 核心代码模式**交付（`template.*` + `user.*` + 函数式 `Solution`）时，除本节下文全部要求外，`gen_data.py` / `gen.py` 产出的 **每一份 `.in` 的 stdin 文本形态** 还须与该题 `题面.md`（含 **PID 抓取** 的原文）中的 **样例输入** 展示格式 **保持一致**（同类分隔符、括号/引号风格、单行或多行结构等）；`template.*` 的解析器必须按同一格式实现。细则与冲突处理见 **`leetcode-core-code-mode` Skill 第 7.0 节**。

**LeetCode 模式下的数据强度（补充）**：在遵守上文「stdin 与样例同形」的前提下，**不得**仅用短样例级、小规模输入凑满 10 组；须按计划使用题面允许上限附近的 **极限数据**（例如极大的 $n$、拉满的字符串/路径长度与深度、值域上下界、长数组/长 JSON 行等），并优先将此类形态落在 **后 2 组大数据** 及必要的构造/hack 组中，以有效压测解析、I/O 与正解在满约束下的行为；若题面未给出明确上限，则按「与题意一致的最大合理规模」构造并在 `data/README.md` 中写明依据。

- **基准 std 选择顺序**（选第一个可用且非空的）：`std.py` → `std.cpp` → `Main.java`（若用户只提供 C++，则应以 `std.cpp` 为造数基准，**不得**因缺少 `std.py` 而直接 fatal，除非 `algorithm-contest-problemsetter` Skill 强制要求 Python）。

生成前确认所选基准可执行；失败则 fatal stop。

### 8.1 必须产出的数据生成脚本（强制）

必须在题目目录下生成**完整可运行**的 Python 数据生成脚本（建议命名 `gen.py`），脚本必须包含：

- **数据生成逻辑**：按题面约束构造输入数据（随机 + 构造混合），并覆盖 `algorithm-contest-problemsetter` Skill 所要求的 6 类测试（样例/基础/边界/随机/构造/hack）。
- **对应解题逻辑**：用于计算标准输出（可直接复用/移植最终采用的基准 std 的核心算法）。
- **文件写入逻辑**：严格按本节的文件与换行规则写入 `.in/.out`。

脚本允许使用第三方库（如 `cyaron`、`numpy` 等）；若使用第三方库，必须保证脚本在本地环境可直接运行，不得给出不可运行的伪代码。

### 8.2 数据组数、目录与命名（强制）

- **共生成 10 组**测试数据：每组一对文件，共 20 个文件。
- **目录**：统一放在 `<题目目录>/data/`。
- **命名**：严格为 `1.in`、`1.out`、…、`10.in`、`10.out`，编号必须连续、从 1 开始。

### 8.3 小/大数据分布（强制）

- **前 8 组为小数据**：范围覆盖题目约束的最小值到中等值，包含极端情况；尽量可用于暴力对拍定位实现错误。
- **后 2 组为大数据**：接近题目约束上限，用于压力测试与复杂度验证。
- **分布均匀**：随机与结构化构造混合，避免极端情况过于集中在少数组。

### 8.4 hack 错误解法数据（强制）

必须显式设计能卡掉常见错误解的数据（如错误贪心、漏边界、溢出、去重/计数错误、把必要条件当充分条件等）。每个 hack 组需要在生成器说明中能解释“在卡哪类错误解”，不得仅靠阴间边界碰运气。

### 8.5 文件末尾换行规则（强制）

- **输入文件（`.in`）**：末尾不能有多余空行——最后一行数据后**不要**换行符。
- **输出文件（`.out`）**：末尾必须有且仅有**一个**换行符。

必须在 `gen.py` 的写文件实现中落实该规则。

### 8.6 生成后自校验（强制）

生成完 10 组后，必须用基准 std（或 `gen.py` 内的解题逻辑）对全部 `*.in` 重新计算并与写出的 `*.out` 做一致性校验；不一致则视为生成失败，fatal stop 并指出首个失败编号与差异摘要。
