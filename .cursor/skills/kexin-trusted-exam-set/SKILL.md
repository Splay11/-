# 可信科目一套题出题 Skill

对齐仓库 `可信题库/` 的题面/题解/代码味道，以及公开信息中的华为可信科目一形态（三级认证；编程卷多为 **3 题**）。算法要精确可评；**题面外壳优先日常生活**（打球、做饭、学校考试等，见 [reference-scenes.md](reference-scenes.md)），不要默认写成机房机器人/链路探针。工程组件留给用户点名或第 3 题多接口。

**默认模式**：用户准备 **3 个空（或指定）题目目录** → 本 Skill 各出 **1 道**：入门级、工作级、专业级。

**单级模式**：用户明确「只要专业级三题」等 → 同级内做 **易→中→难** 递进（仍 3 题）。

### 硬约束（写死）：题面/题解 Markdown 的 `$` 定界

`题面.md` 与 `题解.md` 的**正文**（不含围栏代码块）中：

- **变量名、阿拉伯数字、公式、复杂度**必须用 `$...$` 框起来，例如第 $i$ 个、$n \le 400$、$\gcd(a,b)>1$、$O(n^2)$。
- **禁止**用反引号 `` `...` `` 框上述内容。
- **禁止** `\(...\)`、`\[...\]`、`$$...$$`；独立成行的公式仍写一行 `$...$`。
- **除外**：样例输入/输出、`请实现` 的签名代码块、题解第 3 节五语言代码——围栏内保持源码，不加 `$`。章节名「样例1」等编号不加 `$`。

细节与 `fix/题目格式需求.txt` 一致。写完必须自检：正文里不得残留 `` `变量` `` / `` `数字` ``，也不得出现 `\(`` `\)` `\[` `\]` `$$`。

### 硬约束（写死）：第 3 题 = 多函数业务项目题

**每一套**（默认三级或单级三题）的 **第 3 个目录** 必须是：

- 题面给出一个业务系统/组件类，并 **列出多个成员函数** 供实现（构造 + ≥3 个业务方法，合计公开入口通常 **≥4**）；
- 形态对齐库内 `P5208` 分代 GC、`P5245` TTL 缓存、`P7006` 资源池、`P7011` 证书链、`P5194` Span 等；
- stdin 为 **`ClassName()` + 多行 `method(...)` 调用流**，逐行输出 `null`/`true`/`false`/整数等；
- **禁止**第 3 题做成单函数 `Solution.foo(...)` 的纯算法压轴（区间 DP、最短路等可放在第 1/2 题，或作为该类内部实现手段，但题面对外必须是多方法项目接口）。

### 硬约束（写死）：第 1、2 题从牛客周赛/月赛按难度取材

**仅前两题**（第 1、2 个目录）从牛客周赛/月赛选核；**第 3 题不适用本条**（仍按多函数业务项目出）。

| 套题级别语境 | 第1/2题牛客取材档 |
|--------------|-------------------|
| 入门级（默认第1题，或「仅入门」卷的前两题） | 周赛 / 小白月赛 **A～B**（签到～简单） |
| 工作级（默认第2题，或「仅工作」卷的前两题） | 周赛 **C～D** 或月赛中档 |
| 专业级（「仅专业」卷的前两题；默认三级时第2题按工作级 C～D，若用户只要专业级三题则前两题均 D～E） | 周赛 **D～E** 或月赛偏难档 |

默认三级套卷时的落地：

| 目录顺序 | 级别 | 牛客取材（仅算法核） |
|----------|------|----------------------|
| 第1题 | 入门 | 周赛/小白月赛 A～B |
| 第2题 | 工作 | 周赛 C～D / 月赛中档 |
| 第3题 | 专业压轴 | **不从周赛/月赛对号入座**；多函数业务项目 |

**必须用近期场次（写死）**：

1. 选核前用 WebSearch（关键词：`牛客周赛 Round` / `牛客小白月赛` / `牛客月赛` + 当年年份）或打开 `https://ac.nowcoder.com/acm/contest`，优先 **最近 12～18 个月内** 的周赛/小白月赛/月赛（高编号 Round / 近期场次）。
2. **禁止**默认搬陈年模板题当核，除非用户点名某题。
3. 按上表题号档位选题：先看场次题单（A/B/C/D/E…）与通过率，再打开题面，**只抽取一句话核心题意**（算法观察 + 判定条件），丢弃原故事、原变量名、原样例。

**禁止照搬原题（写死）**：

- **禁止**：翻译/改写原题面、复用原样例数字与情节、沿用原角色与物件名、把原约束原文贴进题面。
- **只允许**：参考核心题意（例如「在约束下求最长合法区间」），然后用 [reference-scenes.md](reference-scenes.md) 抽到的 **自有业务背景** 重新包装规则、接口、样例。
- 选核后：LeetCode 接口 + 全新样例；算法观察可保留，表面必须重做。

蓝图里可对 Agent 内部记下「取材自近期某场周赛 X 的 C 题」；**交付物禁止写出处**——`题面.md` / `题解.md` / `标题.txt` / `data/README.md` / `gen.py` 注释中 **不得**出现 `牛客`、`Nowcoder`、周赛/月赛 Round 号、原题名、「对标 xxx」等字样。

交付形态默认：**LeetCode 核心代码模式**（与 `可信题库` 根目录题一致）。细节执行委派 sibling skills，本 Skill 负责 **套题规划 + 风格冻结 + 完成标准**。

## 1. 调用约定

### 1.1 输入解析

从用户消息提取：

1. **三个题目目录**（必填）：如 `@Problems/P8101 @Problems/P8102 @Problems/P8103` 或 `可信题库/Pxxxx …`。目录不存在则创建。
2. **模式**：
   - 未说明 / 「出一套可信」→ **默认模式**（入门 / 工作 / 专业 各一）。
   - 「入门级三题」「工作级套题」「专业级科目一」→ **单级模式**。
3. **可选约束**：指定算法标签、禁止某考点、业务域（云/安全/运维等）。**不必**再写「第3题要接口」——已是默认硬约束。
4. **不要**假设已有题面；本 Skill **原创出题**（不是 PID 爬取）。若用户粘贴算法核/草稿，可作种子，但仍须写成可信风格完整包。

目录与级别映射（默认模式，按用户给出的顺序）：

| 顺序 | 级别 | `标题.txt` 难度建议 | 形态 |
|------|------|---------------------|------|
| 第 1 个目录 | 入门级 | `2` 或 `3` | 单函数算法题为主 |
| 第 2 个目录 | 工作级 | `4`～`6` | 单函数算法或轻量规则模拟 |
| 第 3 个目录 | 专业级 | `7` 或 `8` | **必须**多函数业务项目题（见上硬约束） |

单级模式：三目录对应同级内 **第1题偏易 / 第2题中等 / 第3题压轴**；难度数字落在该级区间，但 **第3题形态仍必须是多函数业务项目题**（入门级套卷则方法更少、规则更浅，仍是类+多方法，不是单函数）。

### 1.2 每题交付物（硬约束）

每个题目目录必须齐备：

```text
<题目录>/
  标题.txt          # 标题 / 算法标签 / 难度（三行，见下）
  题面.md
  题解.md           # 五语言 + 中文注释（规范强制）
  std.py            # 基准；尽量补 std.cpp、Main.java（及 js/c 若规范要求）
  gen.py
  data/
    1.in … 10.in / 1.out … 10.out
    compile.sh, execute.sh, config.yaml
    template.{cc,java,py,js,c}, user.{cc,java,py,js,c}
    README.md         # 可选：stdin 形态说明
```

`标题.txt` 格式（与 `可信题库` 一致）：

```text
标题：<短中文题名>
算法标签：<逗号分隔，如 模拟 或 动态规划,单调栈>
难度：<整数 2～8>
```

## 2. 套题规划（先于写任何题面）

打开 [reference-levels.md](reference-levels.md)。输出并遵守一份 **套题蓝图**（可写在对话中，不必落盘）：

1. **第1、2题**：按上文牛客档位表选核；**先检索近期周赛/月赛**再定算法核（蓝图写清：核心题意一句话、场次+题号档仅供内部，不进交付物）。**只取核心题意，禁止照搬原题。**
2. **三题算法核**各用一句话；第1/2题标签不撞车；禁止两题都是裸模拟（除非用户只要模拟卷）。
3. **题型搭配**（写死第 3 题）：
   - 第1题：单函数；周赛/小白月赛 A～B 体感（或单级卷对应档）
   - 第2题：单函数为主；周赛 C～D / 专业单级则 D～E
   - 第3题：**仅允许**多函数业务项目接口——生活向如借书/订场/食堂窗口/快递柜，或工程向如 GC、缓存、证书、资源池、租约等
4. **第3题接口清单（蓝图必写）**：类名 + 方法表；方法数不达标 → 蓝图作废。
5. **规模暗示**：随取材档与级别调整；第3题累计调用通常 ≤ 数千～`1e4`。
6. **业务场景（写死，先抽后改）**：打开 [reference-scenes.md](reference-scenes.md)。每题从池中 **随机抽 1 条**，再改写物件名与情节（禁止整句粘贴）。第1/2题默认抽 **日常生活**（打球、做饭、学校考试、食堂、出行等）；第3题可抽生活小系统或工程组件。三题分类不要撞车。用户点名云/安全/运维时才改抽工程条。**禁止**无指定就把背景写成巡检机器人、光纤链路、探针回波、分片副本。禁止公司名。
7. **假解清单**：每题 ≥2 条；第3题针对懒过期/级联/tie-break/幂等。

蓝图未定清（尤其第1/2题核心题意与第3题方法表）→ 禁止开写 `题面.md`。

## 3. 单题工作流（对每个目录执行）

对蓝图中每一题：

### 3.1 业务背景与题面

1. 打开 `fix/prompts/step3_system.txt`、`step3_user.txt`、`fix/题目格式需求.txt`，以及 [reference-scenes.md](reference-scenes.md)。
2. **先抽场景再写背景**：按蓝图已抽到的条目改写成 1～3 句（入门）或 2～5 句（工作）；不要先写算法再硬套「机器人巡检」。生活场景同样要规则可执行，删掉故事后题意完整。
3. 按级别控制背景厚度（详见 [reference-style.md](reference-style.md)）：
   - 入门：`1`～`3` 句场景 + 规则条目
   - 工作：`2`～`5` 句饱满背景 + 形式化
   - 第3题/专业：规则与 **每个方法** 必须写全；背景服务语义，不灌水
4. 题面骨架：
   - **第1、2题**：单函数 `请实现:` + 伪签名；输入多为数组/标量行
   - **第3题（写死）**：`请实现类 $Xxx$` + 方法列表；输入为调用流（见 [reference-style.md](reference-style.md) 形态 B）

```markdown
# 题目内容
…业务系统说明…
请实现类 $FooBar$：
- $FooBar()$：…
- $methodA(...)$：…（成功/失败返回值）
- $methodB(...)$：…
- …
## 输入描述
每行一次调用，首行必为 $FooBar()$。
## 输出描述
每次调用一行：…
## 样例1
（调用流 + 逐行输出 + 说明关键失败/级联）
```

5. **I/O 金标准**：样例输入形态 = `template.*` 与 `gen.py` 的 stdin；第3题必须是调用流同构。
6. 变量名/数字/公式一律 `$...$`（见上文硬约束与 `fix/题目格式需求.txt`）；至少 $2$～$3$ 个样例；第3题样例须覆盖至少一条失败路径与一条交互路径。

### 3.2 题解与标程

1. 章节：`解题思路` → `复杂度分析` → `代码实现`（`题解模板.md`）。
2. 正文与五语言：`题解生成规范(核心代码模式).md`（**五语言皆须实质中文注释**）。
3. 思路须点名算法；工作/专业级写清状态或接口语义。**题解正文不写「常见假解」**（假解只作为 §2 蓝图第 7 条的内部造数依据，不进交付物）。
4. `std.py` 为造数基准；逻辑与题解 Python 同构，可略去教程长注释但保留易错点注释。

### 3.3 数据与 OJ 壳

严格按 **`leetcode-core-code-mode`** 第 3～7 节：

- `data/compile.sh` ← 仓库根 `compile.sh` 原样复制  
- `data/execute.sh` ← `核心代码模式模板/execute.sh` 原样复制  
- `template.*` / `user.*` / `config.yaml` / `1..10.in|out`  
- `gen.py`：固定种子；覆盖样例级、边界、随机、构造、hack；`.in` 与样例同构；换行规则同 generator 第 8.5 节  
- 造数后用 `std.py` 重算校验  

出题质量心智（区分度、hack）对齐 **`algorithm-contest-problemsetter`**。

### 3.4 元数据

写 `标题.txt`：题名与题面一致；算法标签用库内常见短标签；难度落在级别区间。

- [ ] 第3题：失败返回值、幂等/懒更新/级联（若有）、并列 tie-break 已写清  
- [ ] 算法标签不三重复；第1/2题与第3题考点错开  
- [ ] 无公司名；业务可删但仍题意完整  
- [ ] **场景已抽样改写**：第1/2题非默认工业壳（除非用户点名）；三题分类不同；背景来自 [reference-scenes.md](reference-scenes.md) 的抽改而非总用机器人/链路  
- [ ] 每题 `标题.txt` + 题面 + 题解五语言注释 + `data/` 十组 + template/user/compile/execute  
- [ ] **题面/题解正文**：变量、数字、公式均为 `$...$`；无反引号框变量/数字；无 `\(` `\)` `\[` `\]` `$$`（代码块除外）  

任一项失败 → 补齐后再宣告完成。第3题若误做成单函数算法题 → **视为未完成，必须重做第3题**。
第1/2题若误写成陈年经典裸模板、照搬原题、或明显低于/高于对应档 → **换核重做**。
