# 可信题库文风规范

对齐 `可信题库/` 根目录新题（`P523x`/`P524x`/`P525x`/`P530x`/`P700x`）为主；考试子目录旧题可略简，但**新出题按新题风格**。

---

## 1. 题面

### 1.1 气质

- **业务壳 + 可执行规则**：外壳优先来自 [reference-scenes.md](reference-scenes.md) 的**日常生活**（打球、做饭、学校考试、食堂、出行、家务等），工程域（运维/云/安全）是可选池，不是默认。删掉故事后规则仍完整。
- **禁止**无指定时把第1/2题写成巡检机器人、链路探针、分片副本、心跳流水。
- **禁止**真实公司名、品牌名、产品型号凑字；禁止「小苯/小红」人名叙事（用同学/教练/值班师傅等角色即可）。
- 标准术语（子数组、拓扑、前缀）保留；自造业务名可换。

### 1.2 结构（写死）

1. `# 题目内容`（文首可另起题名一级标题，与 `标题.txt` 一致）
2. 背景段落 → 条目化规则 / 公式
3. `请实现:`：第1/2题用单函数伪签名；**第3题用「请实现类」+ 多方法列表**
4. `## 输入描述` / `## 输出描述` + **约束**块
5. `## 样例k`：`输入：` / `输出：` / `说明：`（说明解释规则，不引入新规则）

参考格式细节：`fix/题目格式需求.txt`（**变量名、数字、公式用 `$...$`，禁止反引号与 `\(`/`\[`/`$$`**；样例代码块除外）。

### 1.3 业务背景厚度（结合 `fix/prompts/step3`）

| 级别 | 背景 | 规则密度 |
|------|------|----------|
| 入门 | 1～3 句点明场景与目标 | 低；定义短 |
| 工作 | 2～5 句写饱满（角色/目标/规则来源） | 中；可有「约定/并列时取更小 id」 |
| 专业 | 背景服务接口语义；规则/失败条件必须穷尽 | 高；接口题逐方法写清返回值 |

出题时 **打开** `fix/prompts/step3_system.txt`、`step3_user.txt` 与 [reference-scenes.md](reference-scenes.md)：**随机抽一条再改写**，换场景换术语、背景饱满、禁止公司名。  
（原创题无「原题记法对调」问题时：约束记法在题内自洽即可；同一套三题尽量统一用 `$10^5$` 或统一用 `100000`，不要混用到读着别扭。）

### 1.4 输入形态

**第1、2题 — A. 函数式（默认）**

```text
一行或多行：数组字面量 / 标量
例：
[1, 3, 2]
5
2
```

`请实现: foo(a: int[], x: int) -> int`

**第3题 — B. 类接口调用流（写死，每套必须）**

```text
CertAuthority()
issue(1, 0, 100)
isValid(2, 50)
```

输出逐行：`null` / `true` / `false` / 整数。

题面必须逐条列出类的多个方法（构造 + ≥3 业务方法）。锚点：`P7011`、`P5208`、`P5245`、`P7006`。  
第1/2题若偶发轻量类接口可以，但 **第3题不得退化为单函数**。
### 1.5 样例

- 小而可手算；覆盖主路径 + 至少一条失败/边界路径（接口题尤甚）
- 说明可用列表或逐步代入；专业级接口题说明应对齐关键返回值

## 2. 题解

### 2.0 禁止写竞赛出处（写死）

`题解.md` / `题面.md` / `标题.txt` / `gen.py` / `data/README.md` **不得**出现牛客、Nowcoder、周赛/月赛 Round、原题名、「对标 xxx 题」等字样。只讲本题思路。题面禁止照搬取材原题，只保留自有业务包装后的规则。

### 2.1 骨架

`## 解题思路` → `## 复杂度分析` → `## 代码实现` → `### Python` / `### Java` / `### C++` / `### JavaScript` / `### C`

遵守 `题解生成规范(核心代码模式).md`：**五语言、核心处中文注释**。

### 2.2 思路写法

1. 先点名算法或模型（扫描 / 堆 / DP 状态 / 接口不变量）
2. 步骤化；工作/专业写清易错语义（半开区间、懒删除、严格 vs 非严格栈）
3. 入门可更新手向；专业可直接给状态定义与转移

### 2.3 库内范例气质

- 入门：`P5250/题解.md`（一次扫描说清）
- 工作：`P7005/题解.md`（贡献 + 单调栈）
- 专业：接口题强调语义；DP 题强调状态与复杂度

## 3. 代码

### 3.1 形态

- 算法题：`class Solution` + 题面同名方法
- 系统题：`class MemMgmtSys` / `GCSystem` / `CertAuthority` 等，方法与题面一致
- **无** `main`、无竞赛式快读；I/O 交给 `data/template.*`

### 3.2 风格

- 可读优先，不炫技
- `std.py`：与题解同构，注释可更少但保留易错点
- 并列规则写进比较器/注释（更小 id、更小 key、先到先得等）
- 接口失败：按题面返回 `false`/`-1`/`null` 语义，不抛未说明异常

### 3.3 造数脚本

参考 `可信题库/P5250/gen.py`：

- 固定 `random.Random(种子)`
- 小数组格式带空格：`[1, 2, 3]`；大数组可用紧凑 JSON
- 写 `data/{i}.in` 字节时注意 **in 末无换行、out 末恰一换行**（见 leetcode-core-code-mode / generator 第 8.5 节）
- 维护 `data/config.yaml` 的 `cases` 与 `langs`

## 4. 算法标签用词（与库内一致，短）

常用：`模拟`、`哈希表`、`字符串`、`双指针`、`滑动窗口`、`排序`、`贪心`、`二分答案`、`优先队列`、`栈`、`单调栈`、`DFS`、`BFS`、`拓扑排序`、`最短路`、`动态规划`、`位运算`、`树`、`扫描线`

多个标签逗号分隔，如：`优先队列,模拟,哈希表`。

## 5. 反例（不要这样出）

- 三题都是「读入 n 再暴力枚举」的竞赛入门包，或三题都是机房/机器人/链路工业壳
- 题面数学竞赛腔过重、无 `请实现` 接口
- ACM 多测 `T` 组纯整数流（与可信题库主流不符），除非用户明确要求 ACM
- 题解只有 Python、或五语言无中文注释
- 专业级只靠卡常数区分，无语义/算法深度
