# 编程题面分级改写

逻辑需求不变。按相似度分级改，每一级都包含上一级的改动。从**原题**出发，不要跨级一步改到位。

本题改写是 `problem-pipeline` 第 2 步：只复制改写，不覆盖原始题面。

用户指定级别则只出该级；未指定则四个级别各写一个新文件，不覆盖原题。

| 级别 | 目标相似度 | 在上一级之外允许动什么                                       | 禁止                                       |
| ---- | ---------- | ------------------------------------------------------------ | ------------------------------------------ |
| 一级 | 90%        | 句式、用词、标点、空行、标题层级、数学公式书写、用词不统一（如「配置/方案」） | 改数字、改样例、改背景、改 I/O、整段调序、换变量名 |
| 二级 | 70%        | **必须同时做这三件事**：① 只在每句话内部调语序/换说法；② 正文与约束里的变量名全部换掉；③ 全部样例换新数并手算。写完后与原文不得有连续 $10$ 个汉字一模一样。必要时让最优解唯一以免并列歧义 | 整篇调换段落/条目顺序、换业务故事、改 I/O 字段顺序/行数 |
| 三级 | 50%        | 重构业务背景（仍在相邻领域，如训练集群→推理调度）            | 改成无关故事；改 I/O 协议                  |
| 四级 | 30%        | 输入输出格式（分行、字段顺序、变量名、是否带标签）           | 改核心判定：物品集、约束、目标、要汇报的量 |

## 核心逻辑（四级都必须保住）

先从原题抽出不变式，改写时逐条对拍：

- 决策：每个物品恰好 2 选 1（或原文若是 k 选 1 / 0-1，则保持同一决策）
- 约束：代价之和不超过上限
- 目标：最小化（或最大化）原文那个目标
- 汇报：原文要求输出的量（如最小耗时、实际占用、剩余）语义不变
- 复杂度相关值域：一级～三级尽量不动 $n,C$ 上界；四级若改字段也不要无故放大到改变算法档位

## 一级（90%）

只做「看起来像同一份文档的润色」：

- 局部调换分句内的主动/被动、少量同义替换（不要整段重排；二级也只在句内改，不整篇调序）
- 整理 `# 题目描述 / # 输入描述 / # 输出描述 / # 样例` 结构与空白
- 约束写成规范不等式：$1\le n\le 100$，$1\le C\le 1000$
- 正文与输入说明用词对齐

样例数字、输出、背景名词、变量名、段落顺序、输入行格式全部原样。

## 二级（70%）

在一级文稿上，下面各项**缺一不可**。整题仍按原文的章节和条目顺序写（背景→定义 1、2、3…→输入→输出→样例），**不要**把整篇段落或左右条目对调。

1. **换语序：只动句内，不动篇序**  
   每一句内部可以调主被动、换同义说法、拆合短句，但「先讲什么、后讲什么」跟原题走。例如原文先左后右，二级仍先左后右，不要改成先写输出再写背景。

2. **变量名全部换掉**  
   原文里出现的数组、长度、窗口/上限、下标、左右位置等标识符，二级正文、约束、输入说明里都要换成另一套，并全文统一。例如 $power,k,n,i,left,right$ 换成 $a,t,m,p,L,R$。只换一两个、其余仍用原文名字，不算完成。I/O 仍是原来的行数与字段顺序，只是题面里的称呼变了。

3. **样例全部换新**  
   更换样例中的规模与每一行数字，**手算**新输出。重写样例说明，数字必须和题面一致。不要沿用原题或一级的样例数组。若原样例在最优目标下有多种占用，二级改为唯一最优，或补一句并列规则（须与原意不冲突；原题未定义则优先做成唯一最优）。保留对照性说明时，对照组合也要按新数据重算。

4. **连续十字不得相同（硬门槛）**  
   把原文和二级正文各自抽成汉字序列（去掉空白、标点、Markdown、LaTeX、变量字母和数字；固定标题「题目内容 / 输入描述 / 输出描述 / 样例 / 输入 / 输出 / 说明」也不计入）。二者的最长公共子串长度必须 **小于 $10$**，即不能出现连续十个汉字一模一样。写完用脚本或目视扫一遍；超了就再换句内说法，不要靠整篇调序来躲重复。

## 三级（50%）

在二级文稿上换包装，不换题：

- 换场景与角色名词（任务→作业，配置→规格，集群资源→配额等）
- 二级已换过的变量名默认沿用；若再改字母（$t$→$w$），**行数、每行个数、整数含义顺序仍须与二级相同**
- 不要改到物流/游戏等过远领域；保持「资源配额 + 耗时/代价」这一类计算调度

## 四级（30%）

在三级文稿上改协议，不改判定：

可改：第一行只放 $n$、上限单独一行；四元组改成「耗时在前、配额在后」；三个答案改成三行各一个整数等。

不可改：仍是「每项二选一 + 上限约束 + 同一优化目标 + 同一组汇报量」。

样例数字沿用三级，按新格式重排；说明里的选择与算术结果不变。

## 新标题（硬门槛）

凡本 Skill 产出改写题面并需要新题名时（含写入 `标题.txt`、题面文首 `# …`、题解一级标题、以及上传 `--title`）：

- **长度必须为 $5$～$10$ 个汉字**（只计汉字；不含空格、标点、英文、数字）。少于 $5$ 或超过 $10$ 一律不合格，必须重取。
- 题名要短而贴题：点出核心对象或目标；不要照抄原平台题名。
- `标题.txt`、题面 H1、题解 H1、线上 `update_problem --title` **四处必须同一字符串**。

反例：`连窗日均`（$4$ 字）、`卡槽满载`（$4$ 字）、`限放接单`（$4$ 字）均过短。  
正例：`班次连窗日均`（$6$）、`加速卡槽满载`（$6$）、`作业限放接单`（$6$）。

## 交付

默认写在原题同目录，不覆盖原文件：

- `编程题面_一级.md`
- `编程题面_二级.md`
- `编程题面_三级.md`
- `编程题面_四级.md`
- `标题.txt`（若本轮需要新题名：仅一行题名，或按仓库约定格式，但题名本身须满足上节 $5$～$10$ 字）

文件开头可用 HTML 注释标明级别，便于检查：

```markdown
<!-- 一级：相似度 90%，仅句式/格式 -->
```

## 检查清单

- [ ] 新题名汉字数为 $5$～$10$，且 `标题.txt` / 题面 H1 / 题解 H1 一致
- [ ] 四级都满足核心逻辑对拍
- [ ] 一级样例与原题数字完全一致；一级未整段调序、未换变量名
- [ ] 二级未打乱整题章节/条目顺序；语序只在句内调整
- [ ] 二级与原文汉字串的最长公共子串小于 $10$
- [ ] 二级正文与约束中的变量名已全部替换且全文统一
- [ ] 二级/三级/四级样例已手算，说明与输出一致；二级未沿用原题样例
- [ ] 三级背景仍相邻，未改 I/O
- [ ] 四级 I/O 已变，但决策/约束/目标/汇报量未变
- [ ] 未覆盖原 `编程题面.md`
