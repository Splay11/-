# 客观题题面改写（单选 / 多选 / 判断 / 简答）

面向**非编程**知识题。编程题表面改写仍用 `problem-statement-restyle-flavor`。

## 交付物

| 文件 | 规则 |
|------|------|
| `Problems/P{pid}/题面.md` | **只读保留**原文，不覆盖 |
| `Problems/P{pid}/题面_改写.md` | 改写题面（已存在则 `_v2`…，或用户指定名） |
| `Problems/P{pid}/题解.md` | **必须**与改写后题序、选项字母对齐 |
| `Problems/P{pid}/config.yaml`（及 `data/config.yaml`） | `type: objective` 答案键，与题解一致 |

缺本地题面时：用 `utils/get_problem.py` 拉取到 `题面.md` 再改写（`--base-url https://codefun2000.com`）。

## 硬约束

1. **考点核不变**：同一题考察的知识点、对错语义不变；改后仍能与原知识对齐。数值答案所依赖的关键量不得改到另一档（如卷积通道、汉诺塔 $n$、表达式结构）。
2. **业务背景必须换（写死）**：每题题干要换成新场景、新术语，不要只同义改写原题包装。先交代角色 / 物件 / 规则从何而来（通常 `1`～`3` 句），再进入原考点。禁止保留原题专有叙事（如原「推荐+搜索」仍写推荐搜索）。用户明确说「第 $k$ 题不要换场景」时，仅跳过这些题。
3. **变量名必须换（写死）**：题干、公式、伪代码、表格里的自造符号整题一致替换（如 $n\to k$，$Y=a+bX\to h=\alpha+\beta t$，`step`→`cnt`，表达式 $a,b,c\to u,v,w$）。标准术语与评测字符不换（子段、卷积、dropout；`{{ select }}`；选项里作为答案的具体数字一般保持原值）。伪代码过程名、柱子/栈的标识一并换掉。
4. **评测标记不动**：保留 `{{ select(n) }}` / `{{ multiselect(n) }}`；题号与标记序号连续对应。
5. **版式冻结**：章节（`## 1.单选题` / `## 2.多选题`）、列表 `-` 选项形态、公式定界保持；文首可加中文题名。插图路径不改。
6. **禁止真实公司/品牌名**（改写与点缀均去掉）；技术专名（Transformer、CLIP 等）含义不偷换。
7. **答案必须可追溯**：每改一题就记下「新题号 → 正确选项字母」；题解与 `config.yaml` 同一次改完。题解解析须用**新场景、新符号**叙述，不得混用旧变量名。

## 单选 / 多选怎么改

### 题干与选项

- 题干：**先换业务包装和变量名**（见硬约束 2、3），再换语序；可修原稿笔误（如题干错成别的模型名但选项实为 Whisper → 改对题干）。不要只改措辞、场景和符号仍照抄原文。
- **极性改选项（写死）**：先看题干问的是「哪些/哪项是正确的」还是「哪些/哪项是错误的」，再决定哪些选项能动。题干没写「错误/不正确」时，一律按「问正确」处理。
  - 题干问**哪些选项是正确的**（含单选「下列正确的是」、多选「正确的有」）：**正确的那几个可以不改**，其他选项必须大改、彻底换一个（另写一种明显错法，不得只同义改写；仍须明显错、且不误伤正确考点）。
  - 题干问**哪些是错误的**（含「说法错误的是」「不正确的有」）：**就把正确的都大改**（那些本身为真、不应入选的陈述必须彻底换一种正确说法）；作为答案的错误项可以不改。
  - 纯数字选项（如 $1728$、$1023$）保持原值。被允许保留的选项尽量原文照搬；若题干已换自造符号导致对不上，只改符号对齐，不改考点句子。
- **选项顺序可打乱**；打乱后正确项字母会变，题解/`config` 必须跟新字母。

### 题序（段内打乱）

- **单选段**与**多选段**分开：单选始终整段在前，多选整段在后。
- **只在段内打乱**题目顺序；禁止把多选插进单选段（或反过来）。
- 打乱后重新编号 `1…k`（单选）与 `k+1…n`（多选），`select`/`multiselect` 序号同步。
- 原用 `select` / `multiselect` 的题，挪位后**仍用同类标记**（勿因题号变化乱改标记类型）。

### 题解

- 按**新题序**重写；答案写新字母（多选写 `A、B、D` 这种）。
- 解析跟着新场景、新变量和新选项表述；点明错项错在何处即可，勿冗长。

## 判断题怎么改

- 题干换业务包装与变量名后再重写说法；**题序可打乱**。
- 可把部分原「正确陈述」改成**事实相反的错误陈述**（增加「否」），以拉开区分度；改完后题解必须同步。
- 选项保持：

```text
- 是
- 否
```

- 约定：**是 = A，否 = B**（写入 `config.yaml` 时用字母）。

## 简答 / 场景题怎么改

- **必须**换业务背景与变量名（场景、产品形态、符号、问法措辞）；数值口径以不改变考点为准。
- **核心考查点不变**（如：端侧时延三件套、检索组合、个性化三条路、端云路由规则）。
- 题解按新场景、新符号重写，技术要点与改写前对齐。

## `config.yaml` 格式

单选 / 判断（一项 + 分值）：

```yaml
type: objective
answers:
  '1':
    - C
    - 6
```

多选（选项列表 + 分值）：

```yaml
  '10':
    - - B
      - C
      - D
    - 12
```

- 分值沿用用户给定或同卷惯例（常见单选/判断 6、多选 12）；用户未给则先问或沿用同目录旧 config。
- 答案字母**以当前题解为准**，不要沿用改写前的旧键。

## 上传（用户要求同步线上时）

```powershell
python utils/upload_problem.py --base-url https://codefun2000.com --domain-id system --pid P{pid} --statement "Problems/P{pid}/题面_改写.md" --solution "Problems/P{pid}/题解.md" --no-proxy

# objective 答案键
New-Item -ItemType Directory -Force -Path "Problems/P{pid}/data" | Out-Null
Copy-Item -Force "Problems/P{pid}/config.yaml" "Problems/P{pid}/data/config.yaml"
python utils/upload_testdata.py --base-url https://codefun2000.com --domain-id system --pid P{pid} --data-dir "Problems/P{pid}/data" --no-proxy
```

账号：`HYDRO_API_UNAME` / `HYDRO_API_PASSWORD`（见 `utils/README.md`）。

上传后建议再 `get_problem.py` 拉回比对：线上题面须等于本地 `题面_改写.md`。

## 工作流清单

```text
- [ ] 只读 题面.md + 题解.md，列出每题考点与原答案
- [ ] 写 题面_改写.md（换业务背景 + 换变量名；问正确则保留正确项、其余大改，问错误则正确项都大改；段内打乱）
- [ ] 同步 题解.md（新题序 + 新字母 + 新符号）
- [ ] 写 config.yaml（与题解一致）并复制到 data/
- [ ] 若用户要上线：upload_problem + upload_testdata，并核对线上==本地
```

## 与 flavor 改写的关系

- 可共用：文首题名、换场景换术语、换变量名、无公司名、不写回 `题面.md`。客观题同样要求**每题**换业务背景与自造符号，不是只在卷首点缀一两句。
- 不用：样例重造、I/O 格式、数据范围记法对调等编程题条款。
