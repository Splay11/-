# 题面改写 · 业务点缀版

**算法核不变**（同一实例同一答案）；表面可多维度替换。业务背景按 `fix/` 提示词写饱满（约 2～5 句），不要只剩数学定义。

**业务背景素材（写死，改写前必须打开）：**

| 文件 | 用途 |
|------|------|
| `fix/prompts/step3_system.txt` | 新题面系统规则：场景/术语重做、背景饱满、范围记法对调、I/O 字符集冻结 |
| `fix/prompts/step3_user.txt` | 用户侧约束复述（对照原题面 + 题解代码改写） |
| `fix/prompts/step4_system.txt` | 新样例规则（禁止复用原样例） |
| `fix/题目格式需求.txt` | `# 题目内容` 等章节骨架；变量/数字/公式用 `$...$` |
| `fix/AGENT_REWRITE.md` | Agent 改写硬性约束摘要 |

不要再从 `题面改写知识库/业务背景词库.md` 抽「运维/产线」词条拼 1～3 句点缀；场景与术语按 `step3` 完全重做。

爬取：`utils/get_problem.py` + `utils/README.md`（`--base-url` 固定 `https://codefun2000.com`）。

保 I/O 结构、强制全量换元、短题加厚/长题压薄 → sibling skill **`problem-statement-restyle-io-preserve`**。

本 skill 仍交付 Markdown `题面_改写.md`（含样例），**不要**按 `fix` 流水线输出 JSON 或拆成 `03_*.json` / `04_*.json`。

## 交付物（硬约束 · 调用本 skill 的完成标准）

**一次调用结束时必须齐备：**

| 文件 | 含义 | 来源 |
|------|------|------|
| `Problems/P{pid}/题面.md` | **原题面** | 爬取或已有 / 粘贴 |
| `Problems/P{pid}/题面_改写.md`（或 `_v2`…） | **改写题面** | 本 skill 新写 |

- 只交题面、或改写未产出 = **未完成**。  
- 结束前自检两题面均非空。

## 0. 题面就绪（爬取 + 落盘，改写前强制）

本 skill **可以、且在缺本地原题面时必须**从网站拉取题面再改写。不要让用户先手动另跑一遍爬取。

### 0.1 判定 PID 与目录

1. 从用户消息解析 PID：`P4993` / `4993` / `@Problems/P4993` 等 → 规范为 `P{数字}`。  
2. 题目目录固定为仓库下：`Problems/P{pid}/`（与现有题目布局一致）。  
3. 原题面路径：`Problems/P{pid}/题面.md`。  
4. **无 PID 且无可用本地题面/粘贴题面** → 停止，说明缺 PID 或题面来源。

### 0.2 是否需要爬取

| 情况 | 动作 |
|------|------|
| `题面.md` **不存在**或为空 | **必须爬取**并写入该路径，再改写 |
| `题面.md` 已存在且非空，用户**未**要求重爬 | **不覆盖**；直接用本地文件作只读原文，仍须产出改写文件 |
| 用户明确说「重新爬取 / 覆盖题面 / 刷新题面」 | 允许覆盖写入 `题面.md`，再改写 |
| 用户在对话中粘贴了完整题面且要求以此为准 | 写入 `题面.md` 作为原题面；可不爬；仍须产出改写文件 |

### 0.3 爬取步骤（PowerShell）

依赖：`utils/get_problem.py`、`requests`；环境变量见 `utils/README.md`。

1. 若缺 `HYDRO_API_UNAME` / `HYDRO_API_PASSWORD`，按 README **当场配置到当前 shell**（不要改全局 git/系统无关配置文件，除非 README 要求）。  
2. 创建目录（若不存在）：`Problems/P{pid}/`。  
3. 执行（`--output` 指向目标 `题面.md`；脚本本身以 UTF-8 写入）：

```powershell
$env:HYDRO_API_UNAME="luti"
$env:HYDRO_API_PASSWORD="lutilutiluti1014lutilutiluti"
python utils/get_problem.py --base-url https://codefun2000.com --domain-id system --pid P{pid} --output "Problems/P{pid}/题面.md"
```

4. 校验：`题面.md` 存在且非空；失败则 **fatal stop**，只报告原因，**不要编造题面**，也不要进入改写。  
5. `--base-url` **必须**为 `https://codefun2000.com`；`--domain-id` 默认 `system`（用户另指定则从其指定）。

### 0.4 与「不覆盖原题面」的关系

- **爬取落盘**：保证交付物里的「原题面」就位；仅在 0.2 允许的情况下创建/覆盖 `题面.md`。  
- **改写阶段**：原文 `题面.md` **只读**；改写结果**永远**写到新文件，不得把改写内容写回 `题面.md`。

## 业务背景（强制走 `fix/prompts`）

改写「题目内容」开头的业务包装时，**必须先打开** `fix/prompts/step3_system.txt` 与 `fix/prompts/step3_user.txt`，按其中写死条款执行，不得凭空用词库短句点缀。

1. **写饱满（写死）**：先交代场景里的角色、业务目标和规则从何而来（通常 `2`～`5` 句），再进入形式化定义。不要只有干巴巴的数学描述，也不要无关注水。  
2. **换场景、换术语（写死）**：不能保留原题关键词和专有名词；术语、物件名必须换新。生成一个简洁有吸引力的新标题。  
3. **服务题意**：背景要够，但不要写与求解无关的情节；背景删掉后，题意与硬规则仍完整，不得新增时限、权限等原题没有的条件。  
4. **禁止公司名 / 真人名凑字**：不得出现真实公司/品牌名，也不要用小苯、小红等人名当主角。  
5. **I/O 字符集冻结（写死）**：输入/输出里出现的字符集合必须与原题解代码实际处理的字符一致（如代码比的是 `'0'`/`'1'`，题面不得改成 `L`/`R`）。只允许改字符的业务含义。  
6. **数据范围记法对调（写死）**：只改记法、不改数值。原题科学计数 / `2e5` / $10^9$ → 新题展开成 `200000`、`1000000000`；原题十进制整数 → 新题写成 $10^5$、$2\times 10^5$。模数 $10^9+7$ ↔ `1000000007` 同样对调。禁止与原题同一种记法；禁止把 $2\times 10^5$ 写成 `100000`。

## 输出文件规则（硬约束）

1. **必须**留下原题 `题面.md` + 改写题 `题面_改写.md`；缺一不可  
2. **改写时禁止**把改写结果写回 `题面.md`；目录内其他已有非题面文件不要乱改  
3. 改写文件默认 `题面_改写.md`；已存在则 `题面_改写_v2.md`…；用户指定文件名则用之  
4. 改写阶段：只读 `题面.md`，只写新改写文件（爬取阶段按 §0 写入 `题面.md` 除外）

## Markdown 格式冻结

只改文字与公式内容，保持原题面骨架：

- 不改原有 `# 题目内容` / `# 输入描述` 等章节标题文案；文首**允许新增**题名一级标题；多→单拆样例时可**增补同构**的 `## 样例2`…  
- 不改列表形态、代码围栏/语言标记、表格、公式定界（`$` / `$$`）  
- 不增删评测特殊标记（如 `{{ select(n) }}`）  
- 原样例无说明时，允许按原题 `**输入**` / `**输出**` 同级风格**新增 `**说明**`**

## 多维度表面替换

### 0. 题目名字（必做）

- 为改写后的题面**新起一个中文题名**，放在文首独立一级标题（在 `# 题目内容` 之前），例如 `# 波动贡献最大化`  
- **题名汉字数必须为 $5$～$10$**（只计汉字；不含空格、标点、英文、数字）。少于 $5$ 或超过 $10$ 不合格，须重取。  
- 题名应短、贴题（点出核心对象或目标），**不要**照抄原平台题名/原「小苯/小红」叙事标题  
- 若目录里已有 `题解.md` 且已写题名，题面题名与之对齐；否则题面先定名，题解跟随；有 `标题.txt` 时四处（`标题.txt` / 题面 H1 / 题解 H1 / 线上 title）必须同一字符串  
- 题名只作文案标识，不改变算法核  
- **同步题解时的代码注释（写死）**：若改写后改/重写 `题解.md`，其中 **Python、Java、C++ 三份代码都必须有详细中文注释**。不能只给一种语言写、不能整份只有开头一两句；读入、核心步骤、边界与输出都要有中文说明，禁止英文注释代替。

### 1. 名称

| 类型 | 处理 | 例子 |
|------|------|------|
| 题目自造定义/函数名 | **必须换名** | 平衡度→波动贡献；`B`→`H` |
| 标准术语 | **不换** | 子段、子序列、子数组、前缀、树、边 |
| 业务背景 | 必须换场景与术语，写饱满 | **必须**按 `fix/prompts/step3_*.txt`（见上文「业务背景」） |

### 2. 变量名

整题一致替换：`a`→`v`，`l,r`→`L,R`，函数名同步；禁止混用新旧符号。

### 3. 公式：拆/并 + 展开

- 1～2 步可拆多步：用「其长度为 …」「… 定义为 …」，**禁止**「先令/先取」套话  
- 多步可合并为 1～2 个主公式；语义恒等；不新增改变最优解的因子  
- **下标笼统写法可展开**：  
  - 数组：$\max_{i=L}^{R} v_i$ → $\max(v_L,v_{L+1},\ldots,v_R)$（min/求和/连乘同理）  
  - 对离散取值的 $\min$/$\max$：$\min_{0\le y\le m} f(y)$ → $\min\bigl(f(0),f(1),\ldots,f(m)\bigr)$（项数用 $,\ldots,$ 省略即可）  
- 展开后必须与原记号语义完全一致

### 4. 多询问包装（慎改单组）

**先检查原题能否改成单组：**

| 原题情况 | 改写策略 |
|----------|----------|
| 写了多组/多测，**且**有「所有测试的 $n$ 之和不超过 …」这类 **Σ 规模** | 可以改成真正单组（去掉组数与 Σ）；样例拆成多个 `## 样例k` |
| 写了多组/多测，但**没有** Σ 规模（只有 $T$ 很大、单点 $n$ 很大等） | **必须保留多询问**，否则复杂度与做法可能漂移 |
| 原本就是单组 | 可保持单组；一般不强行改成多询问 |

**保留多询问时的写法（重要）：**

- **不要**写「多组测试数据」「数据组数 $T$」等套话  
- 改写成：**第一行一个整数 $n$（表示随后行数），接下来 $n$ 行每行一个…，对每个…逐一计算/输出**  
- 输出同步为 $n$ 行（每个询问一行）  
- 样例用「多行询问」形态，**新造**数字；可做 1～2 个样例块，每块含若干询问并在说明里逐个点明  

**改成真正单组时：** 不要写「单组测试」；直接「第一行…第二行…」。

### 5. 样例：可改元素，须小而普适，并加说明

- **不要照抄原样例数字/字符串/排列**；自行构造与原题同风格的**小样例**（规模小、好手算、能展示关键规则）；禁止仅删掉 $T$ 后把原多测各组原样拆开当新样例  
- 每个样例的答案必须按**原算法核**算对（可本地暴力/标程核验）  
- 多→真单组时：原多测各组可改写成多个新小样例，不必沿用原数组；多询问保留时：样例用多行询问并新造数字  
- **每个 `## 样例k` 下都要有 `**说明**`**：解释为何输出该结果（可点名划分方式、代入公式的中间量）；说明只帮助理解，不引入新规则  
- 说明的 Markdown 位置：与原题 `**输入**` / `**输出**` 同级；若原题无说明，新增即可

### 6. 数据范围（必做，记法对调）

- **必须按 `fix/prompts/step3` 对调记法**（含多询问行数、单点 $n$、$a_i$ 上界、模数），**禁止**与原题用同一种记法  
- **只换记法、不改数值**：原题 $2\times 10^5$ / $2e5$ → 新题 `200000`（不能写成 `100000`）；原题 `200000` → 新题 $2\times 10^5$  
- 对照：  
  - $2\times 10^5$ ↔ `200000`  
  - $10^5$ ↔ `100000`  
  - $10^9$ ↔ `1000000000`  
  - $10^9+7$ ↔ `1000000007`  
  - $10^{18}$ ↔ `1000000000000000000`（仅当原题是另一种记法时也可用 $1\times 10^{18}$）  
- 真单组化时去掉 Σ；保留多询问时行数上界与原 $T$ 同级（可轻微浮动）  
- 若已有 `data/` / `gen.py`，改范围后确认造数仍落在新范围内

### 7. I/O 措辞与题面内举例

换动词/类型称呼（读入/写出/列表等）；字段顺序与分隔方式不变。输出侧可用略宽但仍真的说法（答案恒 ≥0 时「非负整数」）。

**题面里的教学/示意例子也要换**（如异或、排列、运算演示用的具体数字），**禁止原样照抄**原题例句；换新例子后结果仍须正确，且只起说明作用、不改变题意。正反例须同一设定对齐（如都按长度 $4$），反例要**简短写明为何不成立**。

### 8. 仍禁止

- 改成另一道题；偷换标准术语含义  
- 改浮点精度、多解规则、Yes/No 大小写  
- 覆盖原题面
- 把数据范围改到另一复杂度档（过大或过小）

## 工作流

0. **原题面就位（§0）**：解析 PID → `Problems/P{pid}/` → 按需爬取/落盘 `题面.md` → 校验非空  
1. 只读打开 `题面.md`，抽取算法核（目标、硬规则、单组实例 I/O、自定义名 vs 标准术语）  
2. **打开 `fix/prompts/step3_system.txt`、`fix/prompts/step3_user.txt`**（必要时再读 `fix/题目格式需求.txt`），按其中规则写饱满业务背景（角色 / 目标 / 规则来源，约 2～5 句），再形式化  
3. 压缩题意 + 名称/变量/公式（含展开）替换；范围记法对调；I/O 字符集冻结；**写入** `题面_改写.md`（或 `_v2`…）  
4. 按规则决定真单组 vs 多询问包装；按 `fix/prompts/step4_system.txt` **新造**小样例并写满说明  
5. **交付自检（必须）**：  
   - `题面.md`、改写题均非空  
   - 算法核等价、样例答案正确且非原样例、范围已对调记法且未跨复杂度档、无「单组测试/多组测试/先令」套话、业务背景按 `fix/prompts` 写饱满且无公司名、I/O 字符集未改、改写未写回 `题面.md`
