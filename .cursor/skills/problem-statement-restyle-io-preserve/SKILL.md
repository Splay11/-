# 题面改写 · 保 I/O 结构版

与 `problem-statement-restyle-flavor` **共用**：爬取落盘、双题面交付、业务词库、换名、范围换写法、新样例+说明、标程三语言生成并提交原题。

**本版核心差异**：
1. **I/O 结构**与原题相同（多组仍多组、单组仍单组）  
2. **文风**：像 LeetCode 那样**几句话把题意说清**，再加**一句**业务背景；禁止叠床架屋的「形式化复述」

对照：`题面改写知识库/`（`改写对照清单.md`、`业务背景词库.md`、`标程生成与在线提交.md`）。  
爬取：`utils/get_problem.py` + `utils/README.md`。

## 与 flavor 版对照

| 维度 | flavor | **本 skill（保 IO）** |
|------|--------|----------------------|
| 多测 ↔ 单组 | 有 Σ 时可改真单组 | **禁止**；结构冻结 |
| 题干文风 | 轻度包装即可 | **LeetCode 极简题意 + 一句业务**（见下文） |
| 变量名 | 建议替换 | **全文必须全部替换** |
| 样例 | 新造 + 说明 | **必须新造**；组数形态与原题一致 |
| 算法核 / 标程提交 | 不变 / 共用节 | 同左 |

## 交付物（硬约束）

| 文件 / 结果 | 含义 |
|------|------|
| `<题目目录>/题面.md` | 原题面（缺则爬取） |
| `<题目目录>/题面_改写_保IO.md`（已存在则 `_v2`…） | 改写题面 |
| `std.cpp` / `Main.java` / `std.py` | I/O 对齐**原题**协议；**须含中文注释**且用语对齐改写题面 |
| `题解.md`（目录已有，或本次需交付/上传时） | 章节骨架跟仓库 `题解模板.md`；业务词/变量名与**改写题面**一致 |
| 三语言提交反馈 | 见 `标程生成与在线提交.md` |
| 题解上传（用户要求上传/替换网站题解时） | `utils/upload_sol.py`，只换题解正文 |

**题目目录**：用户 `@` 了具体路径（如 `阿里机考题库/.../P4994`）则用该目录；否则默认 `Problems/P{pid}/`。

## 文风（硬约束 · LeetCode 式）

目标形态：

```text
[一句业务背景]。[用最少句子说清：给什么、做什么、求什么]。[必要时一句补硬规则，如「取走后置 0」]。
```

**必须做到：**

1. **极简题意 + 一句业务**：业务来自 `业务背景词库.md`，通常恰好 1 句，不要写成小作文。  
2. **一套定义说完即止**：原题若已有自然语言说明，又用「更形式化地 / 形式化定义 / 等价地 / 换言之 / 也就是说」再展开同一规则 → **改写时只保留一套**，删掉复述段。  
3. **禁止照搬**原题套话：`更形式化地`、`设两次操作依次…`、大段符号重述（除非原题只有符号、没有白话——则改成白话说清，仍不要两套并存）。  
4. **不要**为了「显得严谨」把已说清的收益/操作再列一遍条目。  
5. 公式仅在明显缩短文字时使用；能一句话说清的，不必拆成「其长度为…定义为…」。  
6. 自检：删掉业务句后应像短 LeetCode 描述；通读无「同一规则讲了两遍」之感。  
7. **零歧义（硬约束）**：压缩≠删硬规则。凡影响答案的**状态顺序 / 立即生效 / 清零后再算**等，必须在题干里写清到「只可能有一种操作顺序理解」；禁止写成可被读成「先累加两次再统一清零」「两次独立加原矩阵」。由顺序自然推出的推论（如交点不再计入）**不必点破**，留给读者。极简与无歧义冲突时，**无歧义优先**（可多 1 句澄清顺序，仍禁止两套形式化复述、禁止堆推论说明）。  
8. **排版换行（硬约束）**：极简≠糊成一段。**题面**（`# 题目内容` / `# 输入描述` / `# 输出描述`）与**题解**（`## 解题思路` / `## 复杂度分析`）凡该断句/分层处必须换行，禁止整段挤成一行难读。

### 排版细则（题面与题解）

| 位置 | 要求 |
|------|------|
| 题目内容 | 业务句、任务目标、关键定义/规则、求解目标宜分段；多种操作/选项用列表；公式可单独成行；定义句与任务句不要硬接在同一长句里 |
| 输入描述 | 先总述组数形态，再分行/分条写：组数 → 每组各行字段与范围 → Σ 约束；禁止用分号把整段输入格式串成一句 |
| 输出描述 | 可短，但仍与输入段风格一致；多组时写清「每组一行/每组……」 |
| 样例说明 | 每组一条，用列表 |
| 题解·解题思路 | 问题转化、关键观察、做法步骤、正确性要点宜分段；分支/步骤用列表；公式单独成行；禁止把整段贪心/DP 推导糊成一句超长段落 |
| 题解·复杂度 | 时间与空间可分行；若有「全体 Σ」约束，可单独一句 |

自检：预览 Markdown 时，输入描述应呈条目/编号列表；题目内容与题解思路均不应出现「一眼扫不过去」的超长单段。

### 篇幅

| 原题 | 改写 |
|------|------|
| 短或长 | **一律偏短**：极简题意 + **约 1 句**业务 |
| 原题特别啰嗦 | **大幅压缩**，合并重复定义 |
| 原题极短但规则易歧义 | 可多 **1** 句澄清硬规则，仍禁止二次形式化复述 |

禁止公司名；词库禁用清单适用。

## 0. 题面就绪

1. 解析 PID 与题目目录（见交付物）  
2. `题面.md` 空/不存在 → `get_problem.py` 写入；已有非空且未要求重爬 → 不覆盖  

```powershell
$env:HYDRO_API_UNAME="luti"
$env:HYDRO_API_PASSWORD="lutilutiluti1014lutilutiluti"
python utils/get_problem.py --base-url https://codefun2000.com --domain-id system --pid P{pid} --output "<题目目录>/题面.md"
```

失败则 fatal stop。改写不得写回 `题面.md`。

## 多维度表面替换

### 0. 题目名字（必做）

文首中文题名；短、贴题。

### 1. 名称

自造定义必须换；标准术语不换。

### 2. 变量名（强制全量）

每个变量映射到新名，全文一致；禁止混用。

### 3. 公式

优先白话；需要时再写公式。禁止「先令/先取」。

### 4. I/O 结构（冻结）

多组仍多组、单组仍单组；字段顺序不变。措辞可换（读入/写出等）。范围换写法、轻改数、不跨复杂度档；有 Σ 则保留并换写法。**输入/输出描述必须分行分条**（见上文「排版细则」），不要整段一句写完。

### 5. 样例（必须新造）

不照抄数字；小样例；答案按原核验算；组数形态与原题一致；每样例有 `**说明**`（说明也要短，不要复述整题规则）。

### 6. 仍禁止

改算法核；偷换术语；改精度/多解/Yes-No；覆盖原题面；把范围改到另一复杂度档；**堆「更形式化地」类复述**。

## Markdown 格式冻结

保留 `# 题目内容` 等章节标题；可增题名与 `**说明**`；不增删 `{{ select(n) }}`。

## 题解与代码注释对齐（硬约束）

改写题面后**必须**检查目录内已有 `题解.md` 与标程/题解代码块中的**中文业务用语**：

1. **对照**：列出原题面业务词（如「荆棘 / 锋利度 / 人名叙事」）与改写题面用词（如「工件 / 硬度 / 耐久」）及变量映射表。  
2. **题解**：若题解仍大量使用原题业务背景，或变量名与改写题面相差很大 → **改写 `题解.md`**，使叙述、符号与改写题面一致；算法核可不变。  
3. **格式**：题解章节骨架遵循仓库根目录 `题解模板.md`（`## 解题思路` / `## 复杂度分析` / `## 代码实现` + `### Python` / `### Java` / `### C++`）。**解题思路与复杂度须按「排版细则」换行分条**，不得整段糊成难读长句。  
4. **标程**：三份 `std.cpp` / `Main.java` / `std.py` **必须带中文注释**；注释与标识符语义对齐**改写题面**（禁止注释里残留原题专有业务词）。题解代码块与磁盘标程应同一套用语。  
5. **上传题解**：用户要求上传/替换网站题解时，用改写后的 `题解.md` 调用：

```powershell
$env:HYDRO_API_UNAME="luti"
$env:HYDRO_API_PASSWORD="lutilutiluti1014lutilutiluti"
python utils/upload_sol.py --base-url https://codefun2000.com --domain-id system --pid P{pid} --solution-file "<题目目录>/题解.md"
```

只替换题解；不要顺带上传测例/改标题，除非用户另有要求。  
6. 目录**没有**题解且用户未要求写题解 → 可跳过题解文件；但本次新写的三标程仍须有中文注释。

## 工作流

0. 原题面就位  
1. 读词库抽 **1 句**业务；用 LeetCode 文风压缩题意（删复述）  
2. 全量换元 + 保 I/O → 写入 `题面_改写_保IO.md`  
3. 新造样例并核验  
4. 按 `标程生成与在线提交.md` 生成**带中文注释**的三标程并提交、反馈未通过  
5. **检查并改写题解/注释业务词**（见上节）；用户要求则 `upload_sol` 替换网站题解  
6. 自检：文风无二次复述；**状态类硬规则无歧义**；**题面与题解已合理换行分条**；I/O 结构未变；变量已全换；题解/注释无旧业务词残留；两题面+三标程+提交结果齐全
